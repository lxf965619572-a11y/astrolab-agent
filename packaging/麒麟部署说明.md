# 使用场景：麒麟操作系统 + 局域网 Qwen3.8-27B

工程师的电脑装银河麒麟桌面操作系统，局域网里有一台模型服务器用 vLLM（或 SGLang）跑 Qwen3.8-27B。AstroLab 装在每台麒麟电脑上，智能体调用局域网的模型，代码和文档不出局域网。和 Windows + 内网 DeepSeek 的场景并行，程序是同一份，差别只在安装包、设置文件和模型参数。

```text
麒麟电脑（每人一台，x86_64 或 aarch64）                        模型服务器（局域网）
┌──────────────────────────────────────┐   OpenAI 兼容接口    ┌──────────────────────────┐
│ AstroLab（Electron）                  │ ───────────────────▶ │ vLLM  Qwen3.8-27B         │
│  └ 引擎 DSH（bash + bubblewrap 沙箱） │  http://<IP>:8000/v1 │  --tool-call-parser qwen3_coder │
│  └ 工具服务：cppcheck、utest、docgen…  │                      │  --reasoning-parser qwen3  │
│ 系统的 gcc / cppcheck / git           │                      │  --max-model-len 131072    │
└──────────────────────────────────────┘                      └──────────────────────────┘
```

## 1 支持范围

| 项目 | 支持 | 说明 |
|---|---|---|
| 操作系统 | 银河麒麟桌面 V10（SP1 及以后）、V11 | 其他 glibc ≥ 2.31 的发行版（统信 UOS、openKylin、Ubuntu 20.04+）同样可用，没有逐一验证 |
| CPU | x86_64（海光、兆芯、Intel/AMD）、aarch64（飞腾、鲲鹏） | 打包时选 `--arch x64` 或 `--arch arm64`。龙芯（loongarch64）没有 Electron 和 DSH 的预编译包，暂不支持 |
| 权限 | 普通用户 | 装在 `~/.local/opt/AstroLab`，数据在 `~/.local/share/AstroLab`；只有补装系统软件包、设 chrome-sandbox 时要 sudo |
| 模型 | Qwen3.8-27B（vLLM / SGLang） | 其他支持工具调用的模型也行，先用模型探测确认 |

## 2 模型服务器（管理员）

参考脚本 `packaging/linux/server/vllm-qwen3.8-27b.sh`。工作台对服务端只有四个要求，模型探测逐项检查：

1. **工具调用**：`--enable-auto-tool-choice --tool-call-parser qwen3_coder`。智能体的每一步都是工具调用，没有它就不能用。长任务里偶发工具参数解析出错时换 `qwen3_xml`。
2. **思考**：`--reasoning-parser qwen3`，思考内容单独放在 `reasoning` 字段，不混进正文。
3. **上下文**：`--max-model-len` 不小于 131072。每一步都带工具定义和技能（约 1 万 tokens），文档类任务还要读几份材料。显存不够时用 FP8 权重或 `--kv-cache-dtype fp8`，不要把上下文压到 64K 以下。
4. **前缀缓存**：`--enable-prefix-caching`。每一步请求的前面部分都一样，缓存命中后只算新增的部分。

服务器防火墙放行端口（默认 8000），只对办公网段开放。

## 3 打安装包（打包电脑，能上网或能访问内网镜像）

```bash
# 可选：在一台新装的、和目标同版本同架构的麒麟电脑上收集离线系统软件包
bash packaging/linux/collect-debs.sh runtime/debs-aarch64
# 打包（x86_64 电脑也能打 arm64 的包：只下载对应平台的预编译文件）
bash packaging/linux/build-offline-linux.sh --arch arm64 --debs runtime/debs-aarch64 \
     --update-dir /mnt/astrolab/release-kylin-arm64 --registry https://registry.npmmirror.com
# 结果：runtime/dist/AstroLab-<版本>-linux-arm64.tar.gz
```

国内网络慢时设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`、`NODE_MIRROR=https://npmmirror.com/mirrors/node`；完全离线时用 `--electron-zip`、`--node-tar` 给出事先下载的文件。

## 4 安装（每台麒麟电脑，普通用户）

```bash
tar xzf AstroLab-0.1.0-linux-arm64.tar.gz && cd AstroLab-linux-arm64
./install.sh --llm http://192.168.10.20:8000/v1          # 缺 gcc、cppcheck、git、bubblewrap 时加 --with-debs
~/.local/opt/AstroLab/check.sh                           # 自检：报告在 ~/.local/share/AstroLab/check-report-*.md
```

`--llm` 让安装脚本做一次模型探测，把服务端的模型名、上下文、思考参数写进设置文件 `~/.local/share/AstroLab/local.env`（模板是 `config/scenarios/kylin-lan-qwen.env`）。之后从开始菜单或桌面的 AstroLab 打开；**设置 → 模型 → 检测模型** 随时可以再查一次。

## 5 设置文件里和这个场景有关的项

| 项 | 本场景的值 | 说明 |
|---|---|---|
| `DEPT_LLM_BASE_URL` | `http://<服务器>:8000/v1` | 末尾的 `/v1` 不能少 |
| `DEPT_LLM_API_KEY` | `EMPTY` 或服务端的 `--api-key` | vLLM 没设密钥时填任意非空值 |
| `DEPT_LLM_MODEL` | `qwen3.8-27b` | 服务端的 `--served-model-name` |
| `DEPT_LLM_THINKING_FORMAT` | `qwen-chat-template` | 发 `chat_template_kwargs: {enable_thinking, preserve_thinking}`；preserve_thinking 让前几步的思考留在上下文里，多步任务更稳 |
| `DEPT_LLM_CONTEXT_WINDOW` | `131072` | 和服务端 `--max-model-len` 一致；写大了长任务会被服务端拒绝 |
| `DEPT_LLM_MAX_TOKENS` | `32768` | 单次输出（思考 + 回复）上限 |
| `DEPT_LLM_INPUT` | `text` | 服务端带视觉编码器时可写 `text,image` |
| `ASTROLAB_NATIVE_FRAME` | 空 | 窗口右上角没有最小化、关闭按钮时写 `1`，改用系统标题栏 |
| `ASTROLAB_DISABLE_GPU` | 空 | 个别国产显卡驱动下花屏、白屏、闪退时写 `1` |

## 6 麒麟上要注意的几件事

- **命令沙箱**：智能体执行命令前，DSH 把命令关进沙箱（系统只读、只能写工作区）。Linux 上先用 bubblewrap，再用 Landlock（内核 5.13 以上）；两个都不可用时 DSH **拒绝执行命令**（不会不加限制地执行）。麒麟 V10 的内核多是 5.4 / 5.10，所以要装 bubblewrap；如果系统关了非特权用户命名空间（`/proc/sys/kernel/unprivileged_userns_clone` 为 0），请管理员打开或给 `bwrap` 设 setuid。自检的“命令沙箱”一项会说清楚。
- **麒麟安全中心的应用程序执行控制（KySec）**：开着时会拦未签名的程序，包括 AstroLab、node，以及单元测试编出来的测试程序。请管理员把 `~/.local/opt/AstroLab` 和工作区目录加入白名单，或把执行控制设为“警告”。自检会读 `getstatus` 的结果。
- **界面沙箱**：Electron 的 chrome-sandbox 要 root 所有并带 setuid。用户命名空间可用时不需要；都不行时 `start.sh` 用 `--no-sandbox` 启动（界面只加载本机文件、不访问网络）。管理员可以 `./install.sh --system-sandbox` 设好。
- **依赖库**：Electron 需要 libnss3、libgbm1、libasound2、libgtk-3-0、libxss1 等，麒麟桌面版默认都有；自检用 `ldd` 列出缺的库。
- **软件更新**：每种平台一个更新位置（例如 `release-kylin-arm64`），不要和 Windows 的混用；安装包的清单记着平台，放错了软件会拒绝更新。共享目录用 NFS 或 Samba 挂载，路径写进 `ASTROLAB_UPDATE_DIR`。
- **模型能力**：27B 模型比部门的 DeepSeek V4 小，长文档类任务（需求分析、概要设计）更容易漏项。上线前在这个场景下把各环节评测（`evals/`）跑一遍，和 DeepSeek V4 的成绩对比，再决定哪些环节用它。

## 7 不暴露源码地部署（`--protect`）

工作台装在工程师的麒麟电脑上，默认包里是可读的 JavaScript 源码。打包时加 `--protect`，把源码换成 V8 字节码和压缩代码：

```bash
bash packaging/linux/build-offline-linux.sh --arch arm64 --protect --debs runtime/debs-aarch64
```

做了什么（`packaging/linux/protect.mjs`，用安装包自带的 Electron 和 node 编译，和运行时同一套 V8）：

| 部分 | 处理 | 装好后看到的 |
|---|---|---|
| 主进程 + 引擎（`app/main`、`app/engine`，含任务控制、Git、库、模型配置、探测…） | 整体打包压缩后编成 **V8 字节码** | `main.jsc` 和三行的加载桩，无源码 |
| 预加载（`preload.cjs`） | **压缩代码**（界面窗口开了 sandbox，沙箱里的预加载载不了字节码；它只是界面可调用的 IPC 通道清单，没有业务逻辑） | 压缩后的 `preload.cjs` |
| 工具服务（`mcp/*`：Cppcheck、单元测试、文档、知识库） | 每个编成 **V8 字节码** | `server.jsc` + 加载桩 |
| 引擎桥、读取围栏（`bridge.mjs`、`read-fence.mjs`） | **压缩代码**（DSH 按 ESM 文件加载，不能换字节码——换了可能让读取围栏这个安全功能悄悄失效，不冒险） | 压缩后的 `.mjs`，无注释、无可读变量名 |
| 更新器、自检（`updater.mjs`、`selfcheck.mjs`） | 压缩代码（要能独立运行） | 压缩后的 `.mjs` |
| 界面（`app/dist`） | 本来就是 Vite 压缩打包的 | 不变 |
| 技能、配置（`skills`、`config`） | 不处理（技能是 Markdown，引擎运行时要读原文；本次范围只保护代码） | 原样 |

打包/发布机才用的脚本（`release.mjs`、构建脚本、`protect.mjs` 本身）不进安装包。

**界限（要清楚）**：装到别人的麒麟电脑上，有 root 的人总能取到运行时文件，本地程序没法做到绝对不可破。字节码挡住的是常规查看、复制和普通开发者——反编译 V8 字节码要专门的工具和功夫。真正敏感、不能外泄的逻辑不该只靠本地程序保护。
