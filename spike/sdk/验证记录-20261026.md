## 发现的问题与处理

1. **新建或已有的项目文件夹，智能体的命令可能起不来或写不进子目录。** Windows 沙箱要求当前用户对工作区及其下目录有完全控制（`WRITE_DAC`、`WRITE_OWNER`）；D 盘上新建的目录通常只继承“修改”权限。第一次实测命令全部启动失败（`SetNamedSecurityInfoW failed (Win32 5): grantWrite`）；只修根目录后，`.git` 仍不可写（`index.lock: Permission denied`）。
   处理：添加项目时，以用户身份（不提权）给根目录加一条可继承的“本人完全控制”（`icacls <目录> /grant <用户>:(OI)(CI)F`），已有子目录自动继承，再运行 DSH 随包的权限修复脚本。实测后 `.git` 上为 `(I)(OI)(CI)(F)`，`git add` 正常。写入需求 FR-PRJ-05。
2. **沙箱里 Git 钩子用的 `sh.exe` 本身起不来**（`NtCreateDirectoryObject` 致命错误，低完整性进程不能创建命名对象目录）。钩子进程失败时 Git 按“钩子拒绝”处理，提交照样被拦住，即失败即拒绝；在沙箱外（界面发起）钩子正常运行。附带影响：项目自带的 Git 钩子在智能体的命令里都会失败——智能体本来就不该提交，可以接受。
3. **钩子只保护提交历史**，挡不住 `git reset --hard`、`git checkout -- .` 等丢弃未提交改动的命令（`reset --hard` 实测会改工作区，只是更新引用失败）。处理：每个任务开始前记录工作区快照。写入需求 FR-REV-04。
4. **`icacls` 输出是系统代码页（GBK）**，按 UTF-8 读会乱码。正式版调用系统命令时按代码页解码，或只看退出码。
5. **评测时工作区里留着上次的答案，智能体会参考**（cmd_check 那次读了旧的测试和报告）。正式版评测必须准备干净的工作区（FR-EVAL-01）。
