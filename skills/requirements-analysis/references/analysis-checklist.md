# 需求分析检查表（示例版）

本表是起步用的示例，应由部门需求分析负责人结合型号经验和历史问题单补充、修订。

每一项的结论只能是以下三种之一，并写在需求分析报告的“检查表结论”中：

- **需求**：已形成需求条目，写出条目标识
- **不适用**：写明理由
- **待确认**：写出问题编号

## A 输入与范围

| 编号 | 检查项 |
|---|---|
| A1 | 输入材料是否齐全：任务书或技术要求、ICD、单机或硬件说明、上级系统需求；每份是否有编号、版本和日期 |
| A2 | 任务书中引用的文件是否都已提供（指令码表、遥测参数表、ICD 等） |
| A3 | 软件安全关键等级是否明确，等级名称是否属于部门使用的等级划分（如 A/B/C/D 级）；任务书用了“重要”“一般”这类不在划分中的说法时，列为待确认问题 |
| A4 | 目标处理器、主频、存储器配置（PROM/Flash、EEPROM、SRAM 容量，是否带 EDAC）是否明确 |
| A5 | 软件的运行环境是否明确：裸机还是操作系统（及版本），编译器及版本 |

## B 配置项与功能模块

| 编号 | 检查项 |
|---|---|
| B1 | 配置项划分是否有依据，是否写出了理由 |
| B2 | 引导程序与应用程序是否分开考虑，引导程序的功能（自检、加载、校验、切换）是否明确 |
| B3 | 与 FPGA、其他处理器上软件的分工边界是否明确（哪些功能由硬件逻辑完成，哪些由软件完成） |
| B4 | 每个功能模块是否都能追溯到上级条款或明确的派生理由 |

## C 状态和模式

| 编号 | 检查项 |
|---|---|
| C1 | 是否列出了全部工作模式（上电、初始化、正常、安全或最小系统、节能、维护或上注等） |
| C2 | 上电或复位后进入哪个模式是否明确 |
| C3 | 每个模式的进入条件、退出条件是否都有，转换关系是否闭合（不存在进得去出不来的模式） |
| C4 | 每个模式下哪些功能运行、哪些停止是否明确 |
| C5 | 收到当前模式下不允许的指令或转换请求时如何处理是否明确 |

## D 功能

| 编号 | 检查项 |
|---|---|
| D1 | 每个功能的输入、处理、输出是否明确 |
| D2 | 每个功能的触发方式（周期、事件、指令）和周期是否明确 |
| D3 | 输入数据超范围、无效或缺失时的处理是否明确 |
| D4 | 上电初始化的内容、顺序和完成时间是否明确 |
| D5 | 自检内容（RAM、程序区校验、外设）、自检失败后的处理和上报方式是否明确 |
| D6 | 数据处理的算法、精度、量化和工程值转换是否明确或有引用来源 |

## E 外部接口

每个外部接口都要逐项检查。

| 编号 | 检查项 |
|---|---|
| E1 | 接口的物理类型、方向、对端设备是否明确 |
| E2 | 帧格式（同步字、长度、数据区、校验）是否明确，来源是哪份文件 |
| E3 | 多字节字段的字节序是否明确；位字段的位序是否明确 |
| E4 | 校验算法是否明确：算法类型（累加和、CRC）、位宽、计算范围（从哪个字节到哪个字节）、初值 |
| E5 | 速率、周期、响应时间、帧间隔是否明确，是否带容差 |
| E6 | 超时判定阈值、重发次数、通信中断后的恢复方式是否明确 |
| E7 | 数据区容量是否能容纳规定的全部参数（逐项累加核算） |
| E8 | **1553B**：BC 或 RT 角色、RT 地址、子地址分配、消息类型、数据字个数、广播、方式码 |
| E9 | **RS-422/RS-485**：波特率、数据位、校验位、停止位、主从关系、帧间隔 |
| E10 | **CAN**：波特率、标识符分配、帧类型、总线关闭后的恢复 |
| E11 | **遥控指令**：指令码表、指令格式与校验、合法性检查、执行反馈（指令计数、错误计数、最近指令码），重要指令是否需要使能或二次确认 |
| E12 | **遥测**：参数表、各参数的量化方式和工程值转换、下传周期或请求应答方式 |

## F 时间与性能

| 编号 | 检查项 |
|---|---|
| F1 | 实时响应时间（如收到请求到开始应答）是否有数值和测量起止点 |
| F2 | 周期任务的周期、允许抖动是否明确 |
| F3 | 校时方式（广播校时、秒脉冲）、校时精度、本地守时精度是否明确 |
| F4 | 数据时标的来源和分辨率是否明确 |
| F5 | 规定的时间指标与接口速率是否相容（如帧传输时间是否小于规定的响应时间） |

## G 安全性与可靠性

| 编号 | 检查项 |
|---|---|
| G1 | 看门狗：硬件还是软件看门狗、溢出时间、喂狗要求、看门狗复位后的行为 |
| G2 | EDAC 与单粒子防护：存储器刷新（巡检）周期，单错和双错的处理与上报 |
| G3 | 关键数据冗余：哪些数据需要冗余存储（如三取二），存储位置，表决失败时的处理 |
| G4 | 热启动或复位后需要保持或恢复哪些数据 |
| G5 | 故障检测、隔离与恢复：每类故障的判据、处理措施和上报方式 |
| G6 | 危险操作防护：哪些操作需要使能、二次确认或条件互锁 |
| G7 | 安全关键功能是否已标识，并在需求条目中标为“安全关键” |

## H 资源与约束

| 编号 | 检查项 |
|---|---|
| H1 | CPU 负荷、程序存储和数据存储的余量要求是否有数值 |
| H2 | 编程语言、编译器、编码规范（如 GJB 8114）是否明确 |
| H3 | 禁用特性（动态内存分配、递归、浮点等）是否明确 |
| H4 | 在轨维护或程序上注：可上注范围、数据格式、校验方式、生效方式、失败后回退 |
| H5 | 适应性：哪些参数需要可配置或可上注修改，默认值是多少 |

## I 合格性与交付

| 编号 | 检查项 |
|---|---|
| I1 | 每条需求是否都能确定合格性方法（测试、演示、分析、审查） |
| I2 | 验证环境是否明确（地面测试设备、模拟器、单机联试、分系统联试） |
| I3 | 交付文档清单和交付形式是否明确 |
