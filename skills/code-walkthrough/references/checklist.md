# 嵌入式 C 代码走查检查表（示例版）

本表是起步用的示例，应由部门编码规范负责人按 GJB 8114 和部门规范补充、修订。
“Cppcheck”一栏表示 Cppcheck 能否发现该类问题：能 / 部分 / 不能。

## A 内存与数组

| 编号 | 检查项 | Cppcheck |
|---|---|---|
| A1 | 数组下标、循环边界是否可能越界（特别注意 `<=` 与 `<`） | 部分 |
| A2 | `memcpy`/`memset` 等的长度是否经过上限检查 | 部分 |
| A3 | 指针参数使用前是否判空 | 部分 |
| A4 | 有符号下标是否检查了负数 | 不能 |
| A5 | 是否使用了动态内存分配（`malloc`/`free`），是否符合部门规定 | 不能 |

## B 变量与运算

| 编号 | 检查项 | Cppcheck |
|---|---|---|
| B1 | 变量在所有路径上使用前是否已初始化 | 能 |
| B2 | 除数是否可能为 0 | 部分 |
| B3 | 整数运算是否可能溢出、截断，有无符号混用 | 部分 |
| B4 | 浮点数是否用 `==` 直接比较 | 部分 |

## C 中断与并发

| 编号 | 检查项 | Cppcheck |
|---|---|---|
| C1 | 中断服务程序与主程序共享的变量是否声明为 `volatile` | 不能 |
| C2 | 共享的多字节变量、结构体读写是否有临界区保护（关中断或其他机制） | 不能 |
| C3 | 中断服务程序是否足够短，是否调用了不可重入函数 | 不能 |

## D 控制流与可靠性

| 编号 | 检查项 | Cppcheck |
|---|---|---|
| D1 | 等待循环是否有超时退出 | 不能 |
| D2 | 函数返回值是否被检查 | 部分 |
| D3 | `switch` 是否有 `default` 分支 | 部分 |
| D4 | 是否使用了递归 | 不能 |
| D5 | 看门狗喂狗路径是否合理，关键数据是否有冗余保护（如三取二） | 不能 |

## E 平台相关（SPARC 与 D2000）

| 编号 | 检查项 | Cppcheck |
|---|---|---|
| E1 | 通信报文的多字节字段是否显式处理字节序（SPARC 大端、D2000 小端），不依赖主机字节序直接赋值或强转 | 不能 |
| E2 | 把字节缓冲区强制转换成结构体指针后访问，是否可能非对齐（SPARC 上非对齐访问会触发陷阱） | 不能 |
| E3 | 报文结构体是否依赖编译器填充（padding），收发双方布局是否一致 | 不能 |
| E4 | `long`、指针长度在 32 位（SPARC）与 64 位（D2000）上不同，是否有依赖其长度的代码 | 部分 |
