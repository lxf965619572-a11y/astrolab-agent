# GJB 8114-2013 C 语言编程规则表（强制准则）

走查（code-walkthrough）、静态分析（static-analysis）和编码（coding）共用本表。条文取自项目中的 `GJB_8114-2013md/claude_gjb8114/rules/`（按 GJB 8114-2013 整理），只收 C 与 C++ 共用的强制准则 R-1-1～R-1-13，共 122 条；C++ 专用准则（R-2-*）不适用于本部门的 C 代码，未收录。GJB 8114 的建议准则不在原文件中，本表也没有：静态分析报告中“推荐类规则”一项写“规则表未收录建议类准则，未检查”。

部门换用或增加编程约定（如 Q/W-Q-80-18-01A-2024《航天器软件C语言编程约定》）时，按同样的列格式增加或替换本表，报告的“引用文件”和规则编号随之改变；脚本 `gjb-scan.mjs` 的规则编号也要相应调整。

## 检查方式

| 写法 | 含义 |
|---|---|
| 脚本 | `scripts/gjb-scan.mjs` 能扫出来（结果是疑似，必须逐条确认） |
| Cppcheck（规则 ID） | `mcp__cppcheck__run_cppcheck` 的告警能发现，括号中是对应的 Cppcheck 规则 ID |
| 编译（告警） | `mcp__utest__compile_check` 的严格告警能发现，括号中是对应的 GCC 告警 |
| 人工 | 工具查不出或只能查出一部分，必须读代码检查 |

同一条规则有多种检查方式时，工具没报不等于没有违反：标“人工”的规则都要逐个函数看。规则编号的缺号（如 R-1-4-5）是原文件如此。

## 示例

示例取自原规则文件（C++ 写法已改为 C）。

### R-1-1-7 以函数形式定义的宏，参数和结果必须用括号括起来

```c
// WRONG
#define SQUARE(x) x * x
// RIGHT
#define SQUARE(x) ((x) * (x))
```

### R-1-1-23 函数参数表为空时，C 语言必须使用 void 明确说明

```c
// WRONG
int get_value();
// RIGHT
int get_value(void);
```

### R-1-2-4 引起二义性理解的逻辑表达式，必须使用括号显式说明优先级顺序

```c
// WRONG
if (a && b || c)
// RIGHT
if ((a && b) || c)
```

### R-1-2-5 逻辑判别表达式中的运算项必须要使用括号

```c
// WRONG
if (area >= min && area <= max)
// RIGHT
if ((area >= min) && (area <= max))
```

### R-1-3-6 指针变量被释放后必须置为NULL

```c
// WRONG
free(ptr);
// RIGHT
free(ptr);
ptr = NULL;
```

### R-1-3-8 动态分配的指针变量第一次使用前必须进行是否为NULL的判别

```c
// WRONG
int* p = (int*)malloc(sizeof(int) * 10);
p[0] = 42;
// RIGHT
int* p = (int*)malloc(sizeof(int) * 10);
if (p == NULL) { return; }
p[0] = 42;
```

### R-1-4-2 条件判定分支如果为空，必须以单独一行的分号加/* no deal with */注释

```c
// WRONG
else
{
}
// RIGHT
else
{
    ; /* no deal with */
}
```

### R-1-4-7 switch中的case和default必须以break或return终止，共用case必须加/* shared */注释

```c
// WRONG
case CMD_A:
    process_a();
    // fall-through without break
case CMD_B:
    process_b();
    break;
// RIGHT — every case ends with break/return
case CMD_A:
{
    process_a();
    break;
}
// RIGHT — intentional fall-through
case CMD_A: /* shared */
case CMD_B:
{
    process_ab();
    break;
}
```

### R-1-6-5 禁止在运算表达式中或函数调用参数中使用++或--操作符

```c
// WRONG
arr[i++] = 0;
result = compute(a++, b);
// RIGHT
arr[i] = 0;
i++;
result = compute(a, b);
a++;
```

### R-1-6-12 除法运算中禁止被零除，取模同样禁止除数为0

```c
// WRONG
int result = a / b;
// RIGHT
if (b != 0)
{
    int result = a / b;
}
```

### R-1-6-18 禁止使用gets函数，应使用fgets函数替代

```c
// WRONG
gets(buf);
// RIGHT
fgets(buf, sizeof(buf), stdin);
```

### R-1-6-19 使用字符串赋值、拷贝、追加等函数时，禁止目标字符串存储空间越界

```c
// WRONG
strcpy(dest, source);
// RIGHT
strncpy(dest, source, sizeof(dest) - 1);
dest[sizeof(dest) - 1] = '\0';
```

### R-1-7-11 具有返回值的函数，其返回值如果不被使用，调用时应有(void)说明

```c
// WRONG
fopen("file.txt", "r");
// RIGHT — if intentionally ignoring
(void)fopen("file.txt", "r");
// or — check the return value
FILE* fp = fopen("file.txt", "r");
```

### R-1-8-4 使用八进制数必须加/* octal */明确注释

```c
// WRONG
int mode = 0755;
// RIGHT
int mode = 0755; /* octal */
```

### R-1-10-6 禁止使用无实质作用的类型转换

```c
// WRONG — rectX is already float, cast is no-op
Point2f((float)rectX, (float)rectY)
// RIGHT — only cast when it actually changes the type
Point2f(rectX, rectY)
```

### R-1-11-4 枚举元素定义中的初始化必须完整，仅首元素全初始化或全部初始化

```c
// WRONG — partial initialization
enum Status { OK = 0, WARNING, ERROR = 5 };
// RIGHT — all initialized
enum Status { OK = 0, WARNING = 1, ERROR = 2 };
// or — only first initialized, rest auto-increment
enum Status { OK = 0, WARNING, ERROR };
```

### R-1-12-3 禁止对浮点数进行==、!=相等比较，应采用差值小于精度判断

```c
// WRONG
if (a == 0.1f)
// RIGHT
const float EPSILON = 1e-6f;
if (fabs(a - 0.1f) < EPSILON)
```

### R-1-12-5 禁止无符号数与有符号数之间的直接比较

```c
// WRONG
if (signedVal < unsignedVal)
// RIGHT
if (signedVal < 0 || static_cast<unsigned int>(signedVal) < unsignedVal)
```

### R-1-13-12 程序外部可改写的变量，必须使用volatile类型说明

```c
// WRONG
int* hardwareReg = (int*)0x4000;
// RIGHT
volatile int* hardwareReg = (volatile int*)0x4000;
```

### R-1-13-13 禁止在表达式中出现多个同一volatile类型变量的运算

```c
// WRONG
int result = counter + counter;  // two reads of same volatile
// RIGHT
int tmp = counter;
int result = tmp + tmp;
```
