# 嵌入式 C 代码走查

## 步骤

1. **确认范围。**明确要走查的文件或目录、目标平台（`sparc` 或 `d2000`）、软件安全关键等级。目标平台不明时先问用户，不要猜。
2. **运行 Cppcheck。**调用 `mcp__cppcheck__run_cppcheck`，`target` 填目标平台，`includeDirs` 填头文件目录。
3. **甄别告警。**逐条打开告警对应的源码阅读上下文，判定为“问题”或“误报”。误报必须写明理由；不确定的标“待确认”。需要规则说明时调用 `mcp__cppcheck__explain_check`。
4. **人工检查。**Cppcheck 只能覆盖一部分问题。逐个函数阅读源码，按 [references/checklist.md](references/checklist.md) 逐项检查，不能因为 Cppcheck 没报就跳过。
5. **输出结果。**按下方格式输出问题清单，最后给出统计（问题数按严重程度分类、Cppcheck 告警中真实问题与误报各多少）。

## 输出格式

| 序号 | 文件:行号 | 来源 | 检查项 | 问题描述 | 严重程度 | 修改建议 |
|---|---|---|---|---|---|---|

- **来源**：`Cppcheck:<规则ID>` 或 `人工:<检查表编号>`
- **严重程度**：严重 / 一般 / 建议
- **修改建议**：给出 diff 片段或具体改法

## 约束

- 只读走查：不得修改被走查的源文件。修改建议写在报告里。
- 每个问题都要能对应到具体代码行和检查项，不写泛泛而谈的建议。
- 用户要求保存报告时，写到工作区的 `review/` 目录下，文件名包含日期。
