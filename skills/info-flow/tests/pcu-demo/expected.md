# PCU 信息流试用用例

## 输入材料

- `D:\lixf\astrolab-agent\sample\docs\PCU软件研制任务书-示例2.docx`
- `D:\lixf\astrolab-agent\sample\docs\PCU-1553B接口控制文件-示例2.xlsx`

两份均为虚构演示材料。

## 期望要点

- 生成 `diagrams/` 下的模型文件 `.flow.json`，以及全图的 `.md` 和 `.svg`，不生成 Word。
- 工具调用用的是 `mcp__infoflow__validate_info_flow` 和 `mcp__infoflow__render_info_flow`。
- 再出一张总图（`view: "overview"`，用 `specFile`）、一张“间接指令 → 负载继电器”的链路图和 N² 矩阵；N² 矩阵里“没有输入/没有输出”的节点在说明里逐个解释。
- 工具返回的全图交叉数不超过 20 处、穿过节点的线 0 条。
- 图按泳道分组，至少包含：星务计算机（BC）、1553B 总线、应用软件、采集电路、执行机构、数据存储。
- 主链能看出：遥测请求 → 1553B 总线 → 遥测组帧 → 遥测消息；遥控指令 → 遥控指令处理 → OC 指令 → 负载继电器；采集电路 → 数据采集调度 → 遥测/充电/过放。
- 图中用虚线标出至少 3 处待确认：
  - RT 地址：任务书 6.1 写 12，ICD 表 1 写 21。
  - 遥测字数：任务书 4.3.1 写 40 字，ICD 表 2 写子地址 1 为 32 字，表 4 定义到 40 字。
  - OC 脉宽：任务书 4.4 写 80 ms，性能要求写 160 ms ± 10%。
- 文字说明列出跨文件不一致，至少还包括：
  - 遥测刷新周期：任务书 4.3.1/ICD 为 500 ms，性能要求为不大于 100 ms；
  - “支持全部方式码”（任务书 4.3.4）与 ICD 表 3 只列 5 个方式码（原写“遥测响应时间 10 ms / 20 ms”，两份材料里都没有，11-18 改正）；
  - 广播消息是否回送状态字：任务书 4.3.5 要求回送，与 1553B 广播的一般处理方式需要确认。
- 每条主要流向能追溯到任务书或 ICD 的章节/表号；节点 `note` 里写依据章节。
- 运行参数“三份写入”指向 MRAM，EEPROM 只提供默认参数（任务书 7）。
- 工具提醒中的“遥测组帧 ↔ MRAM”读写闭环被解释为正常读写关系，而不是擅自改箭头消掉。

## 不应出现

- 擅自把 RT 地址定为 12 或 21、把遥测字数定为 32 或 40、把 OC 脉宽定为 80 或 160 ms。
- 把 ICD 表 4 的 40 个遥测字逐个画成节点。
- 生成 Word 报告，或修改 `sample/docs` 下的源文件。
- 使用网络、外部命令，或覆盖内容不同的模型文件而不先询问。
- 手改生成的 `.md` 或 `.svg`。
