# 信息流梳理

## 基本思路

**模型和图分开。** 先把文档梳理成一份完整的信息流模型（`<名称>.flow.json`：分组、节点、流向、依据），它是唯一的权威来源；图都是从模型生成的视图。项目再大，模型是完整的，每张图只取一部分，所以不会因为“一张图塞不下”而丢信息或画成毛线团。

| 视图 | 回答什么问题 | 参数 |
|---|---|---|
| 全图 | 小系统（≤ 30 个节点、≤ 45 条流向）的完整信息流 | `view: "full"` |
| 总图 | 分组之间怎么联系（同一对分组的流向合并成一条线） | `view: "overview"` |
| 分图 | 一个分组内部怎么流转、对外有哪些接口 | `view: "group", group: "<分组 id 或名称>"` |
| 链路图 | 一条指令/数据从哪来、经过哪些环节、到哪去 | `view: "chain", focus: ["<起点>"], to: ["<终点>"]` |
| N² 接口矩阵 | 接口齐不齐：谁没有输入、谁没有输出、哪对只有单向 | `render_info_flow_matrix` |
| 交互版 | 上面全部放进一个网页：点方块看上下游、搜节点、找两点之间的路径；大型项目最好用 | `export_info_flow_html`（`suggested` 时自动生成） |

## 适用范围

- **输入**：软件研制任务书、需求规格说明、接口控制文件（ICD）、概要设计等文档，或用户口述的功能/接口要点。支持 .docx/.xlsx/.pdf/.md/.txt。
- **输出**：工作区 `diagrams/` 下的模型文件 `<名称>.flow.json`，每个视图一对 `.md`（图片 + Mermaid 源码 + 统计 + 待确认清单）和 `.svg`，交互版 `<名称>.html`；以及一份文字说明：依据章节、待确认问题、工具提醒。
- **不做**：不生成 Word 报告；不替代需求规格说明；不画详细设计级流程图（函数内步骤用 `detailed-design`）；不修改源文档；不提交 Git。

## 工具

工具由内置的信息流服务 `infoflow` 提供：

- `mcp__infoflow__validate_info_flow`：校验模型，不写文件；模型太大时给出建议的视图。
- `mcp__infoflow__render_info_flow`：出图。第一次直接给规格，工具会把模型存成 `.flow.json`；以后改模型、换视图都用 `specFile`。
- `mcp__infoflow__render_info_flow_matrix`：出 N² 接口矩阵。
- `mcp__infoflow__export_info_flow_html`：出交互版（一个 HTML 文件，不联网，浏览器或工作台“产出”里直接看）。`view: "suggested"` 时会一并生成，不用单独调用；模型改过、只出了单个视图时再调用它更新交互版。

## 步骤

1. **确认材料和范围。** 先问清要梳理哪个配置项、以哪份文件为准、图要粗到什么程度。文档不在工作区时让用户给可读路径；只有口述需求时，先复述分组和主链让用户确认。
2. **读文档。** 用 `mcp__docreader__read_document` 读 .docx/.xlsx/.pdf；长文档先用 `mode="outline"` 看目录，再分段读。.md/.txt 用文件读取工具直接读。重点看：单机概述、功能要求、接口要求、性能要求、可靠性与安全性，以及 ICD 的子地址/指令码/方式码表。
3. **提取分组。** 一般按“外部系统 → 总线/接口 → 应用软件各模块 → 采集/执行 → 存储”划分。分组名用文档里的系统名或模块名，不要自造缩写。大型项目按软件模块分组，一个分组 3～10 个节点。
4. **提取节点。** 节点是功能、接口或数据对象。同一功能的细粒度步骤合并成一个节点；ICD 里逐字定义的遥测字只画成“遥测数据”一类，不逐字展开。每个节点 `id` 全图唯一（n1、n2…），`label` 用短名，`note` 写周期、协议、方向或依据章节。**模型里写全**，不用为了图好看删节点：拆图是视图的事。
5. **提取流向。** 每条 `from → to` 必须有文档依据。`kind` 按含义选：
   - `command`：请求、指令、控制、切换、复位；
   - `data`：采集数据、遥测帧、参数、存储内容；
   - `event`：广播、校时、状态变化、故障通知。
   先画主链（请求→处理→输出），再补存储、反馈和故障处理。不要为了图好看改变箭头方向。
6. **交叉核对。** 任务书、ICD、性能/可靠性章节之间对不上的地方（地址、字数、周期、脉宽、响应时间等），在节点 `note` 里用 `【待确认】` 标出，并在文字说明里列出两处出处。**不要自行选定一个值。** 文档没有的流向不要画；确属推断的，先问用户，确认后在说明里注明“推断”。
7. **校验。** 调 `validate_info_flow`。错误必须改：重复 id、未定义端点、未知 kind。提醒逐条处理：
   - 孤立节点：合并、删除，或说明为什么单独存在；
   - 环：确认是请求/响应、读写闭环还是画错了，是正常闭环就在说明里写明；
   - 重复流向：合并标签；
   - 空分组：补节点或删分组；
   - “一张全图会看不清”：按返回的 `suggestedViews` 出图，不要硬出全图。
8. **出图。**
   - 小系统：`render_info_flow`，直接给规格，`view` 用 `full`，`name` 用配置项名（只写模型名，视图后缀工具会加）。
   - 大型项目：`render_info_flow`，直接给规格，`view: "suggested"`，一次出齐全图（规模允许时）、总图、主要分组的分图、主要链路图和 N² 矩阵。
   - 用户问“某条指令经过哪些环节”：`view: "chain"`，`focus` 给起点，`to` 给终点（只画最短路径）；只想看下游就不给 `to`，节点太多时加 `depth`。
   - 之后出其他视图都只给 `specFile` 和视图参数，不用再给 `name`，文件名跟模型走。
   - 之后改模型：编辑 `.flow.json`（或重新给规格并 `overwrite: true`，要先问用户），再用 `specFile` 重新出需要的视图。工具生成的 `.md`/`.svg` 会直接更新；模型文件内容不同、或有同名手写文件时工具会拒绝，**先问用户**，同意后再传 `overwrite: true`。
9. **检查结果。** 看工具返回的每张图的“交叉数、穿过节点的线、是否清晰”。某张图偏密时，按返回的建议换成总图/分图/链路图，不要把偏密的图交给用户当结论。用文件读取工具看 `.md` 里的统计和待确认清单是否与文档一致。SVG 和 .md 不手工改，要改就改模型重出图。
10. **核对接口。** 调 `render_info_flow_matrix`，看“没有输入/没有输出/孤立”的节点：外部来源、终端执行和存储属正常，其余逐个回到文档确认是否漏了接口，写进待确认问题。
11. **汇报。** 给出：模型文件和各视图文件路径（交互版放在最前面，说一句“点方块看上下游、可以找两点之间的路径”）；分组/节点/流向数；各视图看什么；图例含义（总图里线越粗条数越多、两头箭头表示双向、省略的少量流向见 N² 矩阵；分图里灰色虚线框是外部节点）；主要依据（章节号）；待确认问题（逐条列出两处出处）；工具提醒及处理结果；哪些内容为了可读性没有画进某张图（都在模型和 N² 矩阵里）。

## 约束

- 图上的每个分组、节点、流向都要能回到文档；不能把“应该是这样”画成“文档要求这样”。
- 待确认项不能写成结论，也不能为了消除提醒把冲突值改成一致。
- 模型写全，视图取部分；不要为了让某张图好看而删改模型。
- 工具返回“偏密”的图不作为交付结论，换视图。
- 不在图里放真实型号的敏感数据；示例用虚构材料。
- 不联网、不调用外部命令、不删除文件；工具只写输出目录下的 `.flow.json`、`.md` 和 `.svg`。
- 不生成 Word 报告；用户要正式文档时转 `requirements-analysis` 或文档生成流程。

## 常见错误

| 不应这样做 | 问题 | 应这样做 |
|---|---|---|
| 每条需求画一个节点 | 模型变成需求清单，看不出信息流 | 按功能/接口合并 |
| ICD 每个遥测字都画节点 | 过细，无法阅读 | 只画“遥测数据/遥测帧”类别 |
| 大型项目硬出一张全图 | 线条交叉成毛线团，信息流理不清 | `view: "suggested"`，看总图、分图、链路图和 N² 矩阵 |
| 为了全图好看删掉节点或流向 | 模型不完整，接口核对漏项 | 模型写全，用视图控制每张图的范围 |
| 任务书和 ICD 冲突时自己选一个 | 结论不可追溯，掩盖矛盾 | 节点标 `【待确认】`，说明里列两处出处 |
| 为消除“环”提醒强行改箭头 | 信息流方向失真 | 保留闭环，确认后在说明里解释 |
| 手改 SVG 或 .md | 下次出图就被覆盖，和模型不一致 | 改 `.flow.json` 后用 `specFile` 重出 |
| 直接覆盖不同内容的模型文件 | 丢失上一版，无法对比 | 先问用户，同意后再 `overwrite: true` |
