# 详细设计质量规则

| 规则 | 要求 | 检查方法 |
|---|---|---|
| 完整 | 每个函数（含 static）都有一节；每节的项目都填写；函数清单、第 6 章、代码（逆向）中的函数一致 | 检查脚本 |
| 可追溯 | 第 3.1 节每条需求都在第 8 章中有实现的函数；每个对外函数的需求追溯不为空 | 检查脚本 |
| 有依据 | 每个数值、寄存器、时序能在第 3 章或设计决策表中找到 | 检查脚本（数值出处） |
| 不裁决 | 上级文件之间的矛盾列为待确认问题，不在设计中选一个 | 检查脚本 + 人工 |
| 可测试 | 每个判断写清条件和两个方向的结果；异常写清检查顺序和返回值；不用“适当”“相应”“必要时” | 检查脚本（含糊词） |
| 一致 | 处理步骤、流程图、全局变量表、函数清单之间一致；对外接口与概要设计一致 | 人工 |
| 安全 | 中断共享数据有保护；等待有超时；计数有溢出处理；故障有处理或有待确认问题 | 设计检查表 |
| 可实现 | 时序、执行时间、关中断时长可接受；不在中断中长时间等待 | 人工 |

## 设计决策与待确认问题的界线

| 内容 | 由谁决定 | 写在哪里 |
|---|---|---|
| 内部数据结构、算法、函数划分、变量名、内部常量 | 设计者 | 设计决策表（写理由） |
| 对外接口、返回值含义、时序要求、计数含义、故障处理、工作模式下的行为 | 上级文件 | 上级没有规定或互相矛盾 → 待确认问题；可以在“建议”中写设计方案 |
| 硬件寄存器、位定义、时序 | 硬件接口文件 | 没有 → 待确认问题，不凭经验填写 |

判断方法：这项内容改变后，其他模块、遥测接收方、测试人员或硬件是否会看到不同的行为？会的，就不是设计者能单独决定的。
