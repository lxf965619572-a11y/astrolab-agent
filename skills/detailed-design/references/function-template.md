# 软件单元设计格式（部门模板 4.2.2）

每个函数（包括 static 函数）是一个软件单元，在所属模块一章下占一节，标题为 `#### 4.m.n <函数名> 软件单元设计`（m 是模块序号，n 从 2 开始；4.m.1 是模块设计）。下面 6 个小节的标题、表名、表头照抄，检查脚本按它们读取。表号写成“表 4.m.n-k”，表名照抄。

## 格式

````markdown
#### 4.2.3 uart_send 软件单元设计

##### 4.2.3.1 简述
a) 功能概述：逐字节发送 buf 中的 len 个字节，每字节等待发送保持寄存器空，超时返回。
b) 设计思路：查询发送保持寄存器空标志，用系统节拍计时，单字节超时即返回，不重发（重发由调用者决定，见 HLD-5.4.2.3）。
c) 设计约束：调用者 tm_proc（主循环）；不关中断；每字节最长等待 5 ms（XXYY-PREQ3.2）；栈约 16 字节（估计）。
d) 对应的需求：XXYY-FREQ031、XXYY-PREQ3.2

##### 4.2.3.2 输入输出
函数原型：`uart_result_t uart_send(const uint8_t *buf, uint16_t len, uint16_t *sent)`

a) 函数的形参表和返回值

表 4.2.3-1 函数的形参表和返回值

| 类型 | 长度 | 参数名称 | 描述 |
|---|---|---|---|
| const uint8_t * | 4 字节 | buf | 待发送数据，不能为空 |
| uint16_t | 2 字节 | len | 字节数，0～65535 |
| uint16_t * | 4 字节 | sent | 输出：已写入 DATA 的字节数，不能为空 |
| uart_result_t | 4 字节 | 返回值 | UART_OK：全部发送；UART_ERR_NULL：buf 或 sent 为空；UART_ERR_TIMEOUT：某字节等待超过 5 ms |

b) 软件单元相关的外部通信接口数据元素

表 4.2.3-2 数据元素表

| 数据名称 | 数据来源 | 判断条件 | 有效性判断方法 | 判断结果生存时间 | 数据无效时的处理策略 |
|---|---|---|---|---|---|
| 无（本单元不接收外部输入数据） | | | | | |

c) 软件单元需要访问的全局变量或资源及使用方法

表 4.2.3-3 全局变量或资源表

| 全局变量或资源名称 | 使用方法 | 是否具有原子属性 | 防止原子属性被破坏的解决措施 |
|---|---|---|---|
| UART STATUS 寄存器 | 只读，取 TH 位 | 否 | — |
| UART DATA 寄存器 | 只写 | 否 | — |

d) 处理的中断和信号量

表 4.2.3-4 中断和信号量表

| 中断和信号量名称 | 发起或处理方法 |
|---|---|
| 无 | |

##### 4.2.3.3 局部变量及数据结构

表 4.2.3-5 局部变量及数据结构

| 类型 | 长度 | 参数名称 | 描述 |
|---|---|---|---|
| uint16_t | 2 字节 | i | 当前字节序号，0～len−1 |
| uint32_t | 4 字节 | start | 本字节开始等待时的节拍值 |

##### 4.2.3.4 处理流程
1. buf 或 sent 为空指针时，返回 UART_ERR_NULL，不访问寄存器。
2. *sent 置 0。len 为 0 时返回 UART_OK。
3. 对第 i 个字节（i 从 0 到 len−1）：
   1. 调用 sys_ticks() 记录起点 start；
   2. 读 STATUS，TH = 1 时把 buf[i] 写入 DATA，*sent 加 1，处理下一个字节；
   3. TH = 0 时调用 sys_ticks() 取当前值 now；now − start（32 位无符号运算）大于或等于 5 时返回 UART_ERR_TIMEOUT；否则回到 3.2。
4. 返回 UART_OK。

##### 4.2.3.5 限制条件
- 异常处理：空指针见步骤 1；超时见步骤 3.3，超时时 *sent 为已发送字节数。
- 时序：每字节最长等待 5 ms，len 个字节最长 5×len ms；调用者须保证不超过其时间分配（概要设计 5.4.4.3）。
- 安全性措施：参数检查在访问寄存器之前。

##### 4.2.3.6 其他
调用的函数：sys_ticks、UART_RD、UART_WR。
````

## 各项的写法

| 小节 | 写法 | 不合格的写法 |
|---|---|---|
| a) 功能概述 | 一两句话，说明做什么 | 重复函数名 |
| b) 设计思路 | 用什么方法实现，为什么（引用 D-xxx） | 空着 |
| c) 设计约束 | **调用者和执行环境**（主循环/中断/任务名；可能被中断打断、或在中断中运行的要写出来）、关中断范围、是否阻塞、最长执行时间或等待时间（有依据的写数值，没有的写“待测”）、栈占用估计 | 不写执行环境 |
| d) 对应的需求 | SRS 需求标识；内部函数写“内部函数，支持 <对外函数>”，并写它服务的需求 | 空着 |
| 函数原型 | 与概要设计 5.1.2.2 的对外接口（或代码）完全一致，含 static、const | 只写函数名 |
| 表 -1 形参和返回值 | 每个参数一行：类型、长度（按目标机）、名称、含义和取值范围（写清是否含端点）、单位；**返回值单独一行，参数名称写“返回值”**，列出每种返回值及其条件；无返回值写 void | “参数”“返回结果” |
| 表 -2 数据元素 | 本单元直接处理的外部输入数据（来自总线、串口、AD 等）：来源、判断条件、判断方法、判断结果生存时间、无效时处理，与概要设计 5.2.1.3 一致；不涉及的写“无” | 漏写有效性判断 |
| 表 -3 全局变量或资源 | 读写的全局变量、静态变量、寄存器：使用方法写读/写/读改写；主循环和中断都访问的写“是”，并写保护措施（关中断范围、volatile、先拷贝后使用），与 4.m.1 模块数据一致 | 漏写在中断中也访问的变量 |
| 表 -4 中断和信号量 | 本单元发起或处理的中断、信号量；没有写“无” | — |
| 表 -5 局部变量 | 有意义的局部变量和数据结构；没有写“无” | — |
| 处理流程 | 编号的处理步骤（见下），需要时加流程图 | 整段照抄代码 |
| 限制条件 | 每种异常的检测条件和处理（或引用步骤编号）；边界条件；中断、时序、接口、精度的限制；安全关键功能采取的冗余、异常保护、输入验证；必要时与安全有关的编程建议 | “出错时进行相应处理” |
| 其他 | 调用的函数（本模块函数、外部函数、寄存器访问宏）、其他性能要求 | — |

## 处理流程的要求

- 按执行顺序编号，嵌套用 1.1、1.2 或子列表。
- 每个判断写清条件（`>` 还是 `>=`、含不含端点）和两个方向的结果。
- 多项检查有先后顺序时，写清顺序（单元测试会按顺序设计“两项同时不满足”的用例）。
- 访问寄存器写出寄存器名、写入的值或掩码、访问顺序和时序要求。
- 关中断的范围写清从哪一步到哪一步，并说明每条返回路径都会恢复中断。
- 用自然语言或伪代码，变量名可以用；不要整段照抄代码。
- **写到单元测试可以直接据此推导预期结果的程度。**
- 以下单元必须有流程图（Mermaid，写在处理步骤后面）：中断服务程序；含等待或超时循环的；状态机；有 3 个以上判断分支或嵌套循环的；含故障处理的。流程图与处理步骤一一对应，写法见 flowchart-guide.md。
