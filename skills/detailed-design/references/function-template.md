# 函数设计格式

每个函数（包括 static 函数）一节，标题为 `### 6.x <函数名>`。检查脚本按下表的“项目”名称读取，项目名不要改。

## 格式

```markdown
### 6.3 uart_send

| 项目 | 内容 |
|---|---|
| 原型 | `uart_result_t uart_send(const uint8_t *buf, uint16_t len, uint16_t *sent)` |
| 功能 | 逐字节发送 buf 中的 len 个字节，每字节等待发送保持寄存器空，超时返回 |
| 需求追溯 | TMUS-FUN-031、TMUS-PER-008 |
| 调用者和执行环境 | tm_proc（主循环） |
| 输入 | buf：待发送数据，非空；len：字节数，0～65535；sent：输出已发送字节数，非空 |
| 输出 | 返回值：UART_OK / UART_ERR_NULL / UART_ERR_TIMEOUT；*sent：已写入 DATA 的字节数 |
| 读写的全局数据 | 无 |
| 调用的函数 | sys_ticks、UART_RD、UART_WR |
| 异常处理 | 见处理步骤 1、3.3 |
| 时序和资源 | 每字节最长等待 5 ms（TMUS-PER-008）；不关中断；栈约 16 字节 |

**处理步骤**

1. buf 或 sent 为空指针时，返回 UART_ERR_NULL，不访问寄存器。
2. *sent 置 0。len 为 0 时返回 UART_OK。
3. 对第 i 个字节（i 从 0 到 len−1）：
   1. 调用 sys_ticks() 记录起点 start；
   2. 读 STATUS，TH = 1 时把 buf[i] 写入 DATA，*sent 加 1，处理下一个字节；
   3. TH = 0 时调用 sys_ticks() 取当前值 now；now − start（32 位无符号运算）大于或等于 5 时返回 UART_ERR_TIMEOUT；否则回到 3.2。
4. 返回 UART_OK。

```

## 各项的写法

| 项目 | 写法 | 不合格的写法 |
|---|---|---|
| 原型 | 与代码（或概要设计的接口）完全一致，含 static、const | 只写函数名 |
| 功能 | 一两句话，说明做什么 | 重复函数名 |
| 需求追溯 | SRS 需求标识；内部函数写“内部函数，支持 xxx”，并写它服务的对外函数 | 空着 |
| 调用者和执行环境 | 调用者函数名 + 主循环/中断/任务名。可能被中断打断、或在中断中运行的，要写出来 | 不写执行环境 |
| 输入 | 每个参数的含义、取值范围（写清是否含端点）、单位；读取的寄存器 | “参数” |
| 输出 | 每种返回值及其条件；输出参数；写入的寄存器 | “返回结果” |
| 读写的全局数据 | 变量名和读/写，与第 5.2 节一致 | 漏写在中断中也访问的变量 |
| 调用的函数 | 本模块函数、外部函数、寄存器访问宏 | — |
| 异常处理 | 每种异常的检测条件和处理，或引用处理步骤编号 | “出错时进行相应处理” |
| 时序和资源 | 最长执行时间或等待时间（有依据的写数值，没有的写“待测”）、关中断范围、是否阻塞、栈占用估计 | 不写 |

## 处理步骤的要求

- 按执行顺序编号，嵌套用 1.1、1.2 或子列表。
- 每个判断写清条件（`>` 还是 `>=`、含不含端点）和两个方向的结果。
- 多项检查有先后顺序时，写清顺序（单元测试会按顺序设计“两项同时不满足”的用例）。
- 访问寄存器写出寄存器名、写入的值或掩码、访问顺序和时序要求。
- 关中断的范围写清从哪一步到哪一步，并说明每条返回路径都会恢复中断。
- 用自然语言或伪代码，变量名可以用；不要整段照抄代码。
