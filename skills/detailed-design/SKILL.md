# 航天嵌入式软件详细设计

## 适用范围

- **输入**：软件需求规格说明（SRS）、概要设计说明、硬件接口文件（寄存器说明、ICD、芯片手册摘录）；逆向模式另有源代码。
- **输出**：《软件详细设计说明》（每个模块一份）：函数清单和调用关系、数据设计、逐函数设计、流程图、设计决策、需求追溯、待确认问题；逆向模式另有“代码与上级文件不一致清单”。
- **不做**：不写概要设计（没有概要设计时先问用户：由用户提供、先用 preliminary-design Skill 编写，还是只依据 SRS 写并在文档中注明）；不修改代码；不修改上级文件。

## 两种模式

| 模式 | 什么时候用 | 依据 | 代码的作用 |
|---|---|---|---|
| 正向 | 先设计后编码 | SRS、概要设计、硬件接口文件 | 不读代码。工作区中已有代码时，先问用户用哪种模式 |
| 逆向 | 代码已有，补写设计文档 | 同上 | 只用来确定函数划分、数据结构、实现方式；**设计描述的是上级文件要求的行为**，代码与上级文件不一致的地方单独列出 |

逆向模式最容易犯的错误是“照代码写设计”：代码里有缺陷，文档就把缺陷写成了设计。补写的详细设计以后会作为单元测试的依据，照代码写等于让测试永远发现不了这个缺陷。

## 步骤

1. **确认输入和范围。**列出输入文件（名称、编号、版本）、要设计的模块、模式（正向/逆向）、目标平台（SPARC BM3803/3823/3883 或 D2000）。不明确时先问用户。读取文件：`.docx`、`.xlsx`、`.pdf` 用 `mcp__docreader__read_document`，长文档先看 outline 再分段读完。
2. **摘录设计依据。**从上级文件中摘录与本模块有关的全部规定，原文照录，写入文档第 3 章“设计依据”：
   - SRS 中分配给本模块的需求（需求标识 + 原文）；
   - 概要设计中本模块的职责、对外接口（原型、调用者、执行环境）、使用的外部接口、数据、设计决策；
   - 硬件接口文件中的寄存器、位定义、时序要求、复位状态。

   这一章是数值出处和需求追溯的基础，检查脚本会据此核对。
3. **核对上级文件之间的一致性。**逐项比较 SRS、概要设计、硬件接口文件。数值、编号、处理方式不一致，或 SRS 只写了“应进行故障处理”这类没有具体内容的要求时，列为待确认问题（Q-xxx），引用两处原文。**不替上级选择**；设计中涉及的地方写“【待确认】（见 Q-xxx）”。为使设计能够继续，可以写“暂按 SRS 设计（Q-xxx 确认前）”，同时写出另一种规定对本函数的影响；不能不加说明地选择其中一个。
4. **划分函数。**对外函数必须与概要设计的接口一致（函数名、参数、返回值、调用者、执行环境），认为需要修改的列为待确认问题，不擅自修改。内部函数（static）由设计确定，写清为什么划分出来。文档第 4 章给出函数清单和调用关系，调用关系可以用流程图语法画。
5. **设计数据。**按 [references/design-doc-structure.md](references/design-doc-structure.md) 第 5 章的表格写常量、全局和静态变量、数据结构。每个变量写类型、初值、取值范围、读写它的函数和执行环境（主循环/中断/任务）；主循环和中断都会访问的变量，必须写保护方式（关中断范围、volatile）。
6. **逐函数设计。**按 [references/function-template.md](references/function-template.md) 写每一个函数，包括 static 函数：原型、功能、需求追溯、调用者和执行环境、输入、输出、读写的全局数据、处理步骤（编号）、异常处理、调用的函数、时序和资源。写的时候按 [references/design-checklist.md](references/design-checklist.md) 逐项检查：参数检查顺序、边界是否含端点、每条路径的返回值、寄存器访问时序、等待超时、计数位宽和溢出、中断共享数据、故障处理。
   **写到单元测试可以直接据此推导预期结果的程度**：每个判断写清条件和两个方向的结果，每种异常写清检查顺序和返回值。
7. **画流程图。**以下函数必须有流程图：中断服务程序；含等待或超时循环的函数；状态机；有 3 个以上判断分支或嵌套循环的函数；含故障处理的函数。按 [references/flowchart-guide.md](references/flowchart-guide.md) 用 Mermaid 写在 ```mermaid 代码块中，生成 Word 时会转成可编辑的图形。流程图与处理步骤要一一对应。
8. **记录设计决策。**上级文件没有规定、由设计确定的内容（数据结构、算法、内部函数划分、内部常量）写入设计决策表（D-xxx），写明理由。**设计决策不能改变上级文件规定的、外部可见的行为**（接口、时序、返回值、计数含义、故障处理）；这类内容上级没有规定时，列为待确认问题，可以在“建议”中给出设计方案。
9. **逆向模式：对照代码。**完成第 2～3 步之后再读代码。逐个函数比较代码与设计依据，把不一致写入第 10 章“代码与上级文件不一致清单”（N-xxx），注明代码位置、代码的行为、上级文件的规定、结论（疑似代码缺陷 / 上级文件之间矛盾 / 上级文件未规定）。设计正文按上级文件写；上级文件之间矛盾或未规定的，写【待确认】，并在待确认问题中写明“现有代码的做法”。
10. **自查（必须）。**按 [references/quality-rules.md](references/quality-rules.md) 检查，然后运行：

    ```
    node <本 Skill 所在目录>/scripts/check-design.mjs <详细设计文件> [--code <源代码目录>]
    ```

    逆向模式必须加 `--code`。“必须处理”项逐条改正，“复核”项逐条判断，保留的在回复中说明理由。改完再运行一次，直到没有“必须处理”项，并把统计行告诉用户。
11. **输出。**Markdown 是唯一的源文件，保存为 `<模块目录>/doc/详细设计说明-<模块名>-<日期>.md`。用户要求时：`mcp__docgen__list_templates` 选模板，`mcp__docgen__render_docx` 生成 Word（流程图自动转换，转换失败的原因会在“注意”中列出，要改正后重新生成）；待确认问题、不一致清单用 `mcp__docgen__export_xlsx` 导出，加 `reviewColumns: ["答复", "答复人", "状态"]`。

## 约束

- **不编造。**寄存器地址、位定义、时序、阈值、超时、容量只能来自输入文件或设计决策表；设计决策表中的数值要写理由。没有依据的写【待确认】。
- **不裁决矛盾。**上级文件之间不一致时列为待确认问题，引用两处原文，不写“以概要设计为准”“取较严值”。
- **对外接口与概要设计一致。**需要修改接口时列为待确认问题。
- **不照代码写设计。**逆向模式中，代码不能作为设计依据；“按代码”“代码中为”只能出现在不一致清单和待确认问题的“现有代码的做法”中。
- **可测试。**不写“适当延时”“进行相应处理”“必要时重试”，写出具体的条件、数值、顺序和结果。
- **只读输入。**不修改上级文件和代码。
- **新写设计不沿用旧版本。**用户没有要求修订时，不读取、不沿用工作区中其他版本的详细设计（包括备份目录中的），从输入文件重新做。用户要求在已有设计上修订时，才以它为基础。
- **只读输入和本 Skill 的参考文件。**不读取工作区以外的评测目录、参考设计、其他模块的设计作为样例；格式以本 Skill 的参考文件为准。检查脚本直接运行，不读它的源码。
- **修订也要完整自查。**在已有设计上修改时，对全文重新执行第 10 步。
- **不在外网处理真实型号代码和文档。**使用云端模型时只处理样例或脱敏材料。
- **部门规定优先。**部门有正式的详细设计模板、函数说明格式或流程图规范时，以部门规定为准。

## 常见错误做法

| 不应这样写 | 问题 | 应这样写 |
|---|---|---|
| 概要设计写“遥测帧周期 500 ms”，SRS 写“1 s”，详细设计取 500 ms | 替上级选择 | 列 Q：引用两处原文；设计中写“组帧周期【待确认】ms（见 Q-001）” |
| “EDAC 双错时复位处理器并记录错误地址” | SRS 只写“应进行故障处理”，处理方式是自己定的 | 列 Q，可在建议中写这个方案；设计中写“双错时按【待确认】的方式处理（见 Q-004）” |
| “写分频寄存器后适当等待再使能” | 不可测试，等待时间没有出处 | “写分频寄存器后等待 N 个时钟周期（芯片手册 x.x 节），再写使能位”；手册没写就列 Q |
| 逆向：“发送超时 6 ms（代码中 TX_TIMEOUT 为 6）” | 把代码当依据 | 设计按上级文件写（如 SRS 规定 5 ms）；代码的做法写入不一致清单 |
| “参数非法时返回错误码” | 检查顺序、各情况的返回值都没写 | 按顺序列出每项检查、条件（含不含端点）和返回值 |
| 全局变量表没有“读写者”和“保护”列 | 中断共享数据的保护无从核对 | 每个变量写读写的函数和执行环境，共享的写关中断范围 |
| 流程图中的判断与处理步骤不一致 | 两处描述不同，测试不知道以哪个为准 | 处理步骤为准，流程图节点与步骤一一对应 |
| 对只写寄存器、写 1 清除寄存器做“读-改-写” | 只写寄存器读出值无意义；读-改-写会误清其他位 | 按接口文件的访问属性设计，直接写掩码 |
