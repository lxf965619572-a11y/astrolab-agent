# 时序分析方法

概要设计阶段还没有代码，执行时间只能估计。时序分析的目的是证明执行方案在最坏情况下满足时间要求，并找出必须分步执行、必须用中断的地方。估计值要写明估计方法，结论写“满足（估计，待实测）”，在测试阶段实测确认。

## 1 要分析什么

1. SRS 中每一条有时间要求的需求：响应时间（“收到后 X ms 内”）、周期（“每 X s”）、完成时间（“X s 内完成”）。
2. 接口文件中的每一条时间约束：稳定时间、转换时间、写周期、看门狗超时、缓冲区溢出时间、对端的应答超时。
3. 执行方案本身的参数：主循环最长一轮、最长关中断时间、各中断的最长执行时间和频率。

## 2 估计执行时间

| 方法 | 适用 | 写法举例 |
|---|---|---|
| 存储器和寄存器访问次数 × 访问周期 | 搬移、校验、刷新等以访存为主的处理 | “每字读、写各 3 个时钟周期（HW-2.1），加循环开销按 10 个周期估计，主频 40 MHz 时每字 0.4 μs” |
| 硬件规定的时间 | 转换、写周期、稳定时间 | “转换时间不大于 20 μs（HW-4.3）” |
| 类似代码的实测值 | 协议处理、算法 | “参考某型号同类帧处理实测 30 μs，按 2 倍估计” |
| 指令数估算 | 简单逻辑 | “约 200 条指令，按每条 2 个时钟周期估计” |

估计时取偏大的值，写明倍数。

## 3 主循环最长一轮

连续运行的主循环（前后台结构）中，事件在主循环中被处理，最坏情况是事件刚好在主循环开始处理一个最长的步骤时到达：

```
最长一轮 = Σ（本轮可能执行的每个任务步骤的最长执行时间） + 期间发生的中断处理时间
```

“本轮可能执行”指最坏情况下在同一轮中都到期的任务。分步执行的任务只计一步。

由此倒推：如果最严的响应要求是 R，事件处理本身需要 P，事件检测延迟为 E，则

```
主循环最长一轮 ≤ R − E − P（还要留余量）
```

超过的任务步骤要拆小（状态机），忙等要改为计时判断。

## 4 响应时间

```
最坏响应时间 = 事件检测延迟 E + 等待主循环 W + 处理时间 P + 期间的中断时间 I
```

- **E**：事件到达后多久软件才知道。例如接收中断按门限或超时触发：帧尾字节少于门限时，要等超时（如 4 个字符时间）才产生中断。
- **W**：中断把事件交给主循环后，主循环最多要等多久才处理它，取主循环最长一轮。
- **P**：解析、执行、写输出的时间。
- **I**：W 和 P 期间可能发生的中断处理时间，按最高频率计。

例（虚构）：RS485 接口 1 Mbps，每字符 10 μs，接收中断门限 8 字节，超时 3 个字符时间；指令帧 6 字节。E = 3 × 10 μs = 30 μs；主循环最长一轮 W = 0.8 ms（估计）；P = 50 μs（估计）；1 ms 定时中断 5 μs，期间至多 1 次。最坏响应 ≈ 30 + 800 + 50 + 5 = 885 μs，要求 2 ms，满足（估计，待实测）。

## 5 周期和完成时间

- 用 tick 计数实现的周期任务，周期误差在一个 tick 以内；任务被延迟执行时，还要加上主循环最长一轮。
- 分步执行的处理（如逐路采集、逐页写入）：总时间 = 步数 × 每步间隔（取最坏值）+ 每步本身的等待。验证总时间满足“X 内完成”。
- 用 tick 计时的“等待不少于 X”：起点在两个 tick 之间，等待 N 个 tick 实际只保证 N − 1 个周期，要等 ⌈X/T⌉ + 1 个 tick。
- 在主循环中按 tick 执行的前后两步：前一步可能在 tick 到来后被延迟一整轮主循环才执行，后一步却按时执行，实际间隔会比 N 个 tick 周期短一轮主循环。要求“间隔不少于 X”时，按“N 个周期 − 主循环最长一轮”验证，不能写“软件延迟不会缩短间隔”。

## 6 外设服务间隔

```
最长允许不服务时间 = 缓冲深度 × 字符时间（接收）
实际最长服务间隔 = 中断响应延迟（含最长关中断时间、更高级别中断的处理时间）
                  或 主循环最长一轮（查询方式）
```

后者要小于前者并留余量。例：16 字节 FIFO，1 Mbps 时 160 μs 就会填满，查询方式基本不可行。

## 7 看门狗

```
最坏喂狗间隔 = 喂狗周期 + 主循环最长一轮（喂狗任务被延迟） + 初始化等阻塞段
要求：最坏喂狗间隔 < 看门狗最短超时（考虑公差）× 0.5（建议余量）
```

## 8 CPU 负荷

```
负荷 = Σ（任务最长执行时间 ÷ 任务周期） + Σ（中断最长执行时间 × 中断频率）
```

连续运行的主循环中，没有到期任务时的空转不计入负荷。包含忙等的步骤，忙等时间计入负荷。中断和事件任务的频率按接口允许的最高频率计（如对端规定的最小帧间隔、线路满速），不按正常流量计。

## 9 写法

6.4 节表格每行一个分析项，表后分条写计算过程：

```markdown
| 编号 | 依据 | 时间要求 | 最坏情况路径 | 最坏情况时间 | 结论 |
|---|---|---|---|---|---|
| TA-01 | XXX-PER-003 | 收到指令后 2 ms 内输出 | 接收超时 → 主循环最长一轮 → 解析和输出 | 0.9 ms | 满足（估计，待实测） |

TA-01：E = …；W = …；P = …；合计 …。
```

结论只能是“满足”“不满足”“待实测”，估计得到的写“满足（估计，待实测）”。不满足的，在表后写改进措施或列为待确认问题。
