# 概要设计质量规则

| 规则 | 要求 | 检查方法 |
|---|---|---|
| 完整 | SRS 的每条需求都摘录在 3.1 节；章节齐全；每个模块在 7.2 节有接口小节 | 检查脚本（`--srs` 对照原文件） |
| 可追溯 | 3.1 节每条需求都在需求追溯表中有模块；模块表中每个模块都有分配的需求；两张表一致 | 检查脚本 |
| 有依据 | 地址、中断级别、时序、容量、速率能在第 3 章或设计决策中找到；估计值写明估计方法 | 检查脚本（数值出处） |
| 不裁决 | 上级文件之间的矛盾列为待确认问题，不在设计中选一个 | 检查脚本 + 人工 |
| 时序可证 | 每条时间要求、每条硬件时间约束都有最坏情况分析和结论；结论与计算一致 | 检查脚本 + 人工 |
| 安全 | 共享数据有保护；外设服务间隔小于缓冲溢出时间；看门狗喂狗间隔有余量；安全约束在唯一出口检查；故障有处理或有待确认问题 | 检查表 |
| 可展开 | 每个模块的职责、接口、执行环境写到详细设计可以直接展开的程度 | 人工 |
| 资源 | CPU、程序存储器、数据存储器都有估算和结论 | 检查脚本 |

## 设计决策与待确认问题的界线

| 内容 | 由谁决定 | 写在哪里 |
|---|---|---|
| 执行模型、tick 周期、模块划分、中断是否嵌套、缓冲区大小、分步执行方式、内部数据结构 | 设计者 | 设计决策表（写理由） |
| 对外接口（帧格式、速率、遥测内容）、时间要求、计数含义、故障处理方式、工作模式下的行为、安全约束超限时的处理 | 上级文件 | 上级没有规定或互相矛盾 → 待确认问题；可以在“建议”中写设计方案 |
| 地址、中断分配、寄存器、时序 | 硬件接口文件 | 没有 → 待确认问题，不凭经验填写 |

判断方法：这项内容改变后，平台、地面、其他单机、测试人员或硬件是否会看到不同的行为？会的，就不是设计者能单独决定的。

## 概要设计与详细设计的分工

| 内容 | 概要设计 | 详细设计 |
|---|---|---|
| 模块 | 划分、职责、需求分配 | 模块内的函数划分 |
| 接口 | 模块对外函数原型、调用者、执行环境、返回值含义 | 每个函数（含 static）的输入输出、处理步骤 |
| 执行 | 调度表、中断分配、最长执行时间预算、分步执行方式 | 状态机的状态和转移、每一步的处理 |
| 数据 | 关键数据、共享数据保护方式、存储分配 | 变量定义、初值、取值范围 |
| 时序 | 最坏情况分析，给出每个模块的执行时间预算 | 按预算实现，误差分析到函数级 |
