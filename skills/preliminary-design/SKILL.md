# 航天嵌入式软件概要设计

## 适用范围

- **输入**：软件需求规格说明（SRS）、硬件接口文件（存储器映射、中断分配、寄存器、时序）、通信协议或 ICD；可能还有研制任务书。
- **输出**：《软件概要设计说明》（每个配置项一份）和待确认问题清单。它是详细设计的输入：每个模块的职责、分配的需求、对外接口、执行环境、使用的接口要写到详细设计可以直接据此展开的程度。
- **不做**：不写函数内部的处理步骤（那是详细设计）；不写需求（SRS 有缺漏时列为待确认问题）；不修改上级文件。
- **只做正向设计。**工作区中已有代码时，先问用户：是按上级文件重新设计，还是为已有代码补写概要设计。补写时，代码只用来确定模块划分和接口；代码与上级文件不一致的地方列为待确认问题，写明“现有代码的做法”，设计正文仍按上级文件写。

## 步骤

1. **确认输入和范围。**列出输入文件（名称、编号、版本）、配置项名称、目标平台（SPARC BM3803/3823/3883 或 D2000）、有无操作系统。不明确时先问用户。读取文件：`.docx`、`.xlsx`、`.pdf` 用 `mcp__docreader__read_document`，长文档先看 outline 再分段读完。**SRS 的每一条需求都要读到**，不能只读目录或摘要。
2. **摘录设计依据。**写入文档第 3 章，原文照录：
   - 3.1：SRS 的**全部**需求（需求标识 + 原文），包括约束、资源、质量因素类需求；
   - 3.2：硬件接口文件和协议中与软件设计有关的条款：存储器映射、中断分配、外设的缓冲深度和时序要求、复位状态、看门狗、非易失存储器的写入特性、通信速率和帧格式。

   这一章是数值出处和需求追溯的基础，检查脚本据此核对。
3. **核对上级文件之间的一致性。**逐项比较 SRS 与每份接口文件：速率、帧长和字段（把字段长度加起来核对总长）、编号方式、数值的单位和含义、时间要求；SRS 中只写“应进行故障处理”这类没有具体内容的要求。不一致或没有规定的列为待确认问题（Q-xxx），引用两处原文。**不替上级选择**；为使设计能够继续，可以写“暂按 SRS 设计（Q-xxx 确认前）”，同时写出另一种规定对设计的影响。
4. **定 CSCI 级设计决策。**执行模型（前后台、时间片调度、操作系统任务）、时基（tick 周期）、哪些外设用中断、是否允许中断嵌套、共享数据保护的统一方法、故障处理的统一方法、编程语言和编码规范。写入第 4 章设计决策表（D-xxx），每条写理由。
5. **划分模块并分配需求。**按 [references/architecture-checklist.md](references/architecture-checklist.md) 第 1 节划分：驱动与业务逻辑分开；每个硬件输出只有一个模块写它；安全约束（互锁、数量限制、模式限制）放在所有路径都必须经过的那个模块中。第 5.2 节的模块表写每个模块的职责、执行环境和分配的需求；**SRS 的每一条需求都要分配到模块**，每个模块都要有需求依据（基础模块追溯到约束类或质量因素类需求）。
6. **设计执行方案。**写入第 6 章：
   - 启动和初始化流程（流程图），说明初始化期间的输出状态、喂狗、初始化总时间；
   - 主循环和任务调度表：每个任务的触发方式、周期、最长执行时间（估计值）；
   - 中断表：中断源、级别、处理程序、处理内容、最长执行时间、是否允许嵌套；
   - 共享数据表：每个被中断和主循环共同访问的数据的写者、读者、保护方式。

   **从最严的响应时间要求倒推每一步允许的最长执行时间**：主循环中任何一步（包括外设等待）都不能超过它，超过的改为分步执行（状态机），不能忙等。
7. **做时序分析。**按 [references/timing-analysis.md](references/timing-analysis.md)，对 SRS 中每一条有时间要求的需求、接口文件中每一条时间约束（稳定时间、写周期、超时、缓冲区溢出时间、看门狗超时）给出最坏情况路径、计算过程和结论，写入 6.4 节。估计值写明估计方法，结论写“满足（估计，待实测）”；算不出的写“待实测”并说明在哪项测试中测量，**不能不分析就写“满足”**。
8. **设计接口。**7.1 节列出全部外部接口（对端、依据、实现模块）；7.2 节每个模块一小节，列出对外接口（函数原型、调用者、执行环境、返回值含义、是否可重入）和使用的其他模块接口。接口要能直接作为详细设计的依据。
9. **设计数据和存储。**8.1 节列出关键数据（遥测量、计数、参数、状态）的所属模块、存储位置、保护或冗余方式；8.2 节给出存储分配（程序区、数据区、栈、参数区），地址来自接口文件。
10. **估算资源余量。**第 9 章逐项估算 CPU 负荷、程序存储器、数据存储器（含栈）、非易失存储器，写明估算方法和结论，与 SRS 的余量要求比较。
11. **可靠性和安全性设计。**第 10 章逐条落实 SRS 的安全性、可靠性需求，并按检查表第 9～11 节检查：看门狗、EDAC 和存储器刷新、关键数据冗余、指令防护、上电和复位状态、故障检测和处理。上级文件没有规定处理方式的，列为待确认问题，可以在“建议”中给方案。
12. **写需求追溯。**第 11 章，SRS 每条需求对应的模块。
13. **自查（必须）。**按 [references/quality-rules.md](references/quality-rules.md) 检查，然后运行：

    ```
    node <本 Skill 所在目录>/scripts/check-hld.mjs <概要设计文件> --srs <SRS 文件>
    ```

    `--srs` 用输入的 SRS 原文件（.docx 或 .md），脚本据此核对第 3.1 节是否漏摘需求。直接运行脚本，不需要读它的源码；不要为了让脚本不报而改写法（如给数值加“约”字），而要按提示核实内容。“必须处理”项逐条改正，“复核”项逐条判断，保留的在回复中说明理由。改完再运行一次，直到没有“必须处理”项，并把统计行告诉用户。
14. **输出。**Markdown 是唯一的源文件，保存为 `<配置项目录>/doc/概要设计说明-<软件简称>-<日期>.md`。用户要求时：`mcp__docgen__list_templates` 选模板，`mcp__docgen__render_docx` 生成 Word（流程图自动转换，转换失败的原因会在“注意”中列出，要改正后重新生成）；待确认问题用 `mcp__docgen__export_xlsx` 导出，加 `reviewColumns: ["答复", "答复人", "状态"]`。

文档结构和表头见 [references/hld-doc-structure.md](references/hld-doc-structure.md)，流程图写法见 [references/flowchart-guide.md](references/flowchart-guide.md)。

## 约束

- **不编造。**地址、中断级别、时序、容量、速率只能来自输入文件或设计决策表；设计决策中的数值写理由。执行时间等估计值写明估计方法，并注明“估计”。没有依据的写【待确认】。
- **不裁决矛盾。**上级文件之间不一致时列为待确认问题，引用两处原文，不写“以 SRS 为准”“取较严值”。
- **不放宽需求。**时序分析不满足时，改设计或列为待确认问题，不改用较宽的指标。
- **需求全部分配。**SRS 的每一条需求都在模块表和需求追溯表中出现，包括资源、质量因素、设计约束类需求。
- **写到概要设计为止。**模块的对外接口写到函数原型；函数内部的处理步骤留给详细设计。但影响时序和资源的实现方式（分步执行、中断驱动、双缓冲）要在概要设计中定下来。
- **只读输入。**不修改上级文件。
- **新写设计不沿用旧版本。**用户没有要求修订时，不读取、不沿用工作区中其他版本的概要设计（包括备份目录中的），从输入文件重新做。用户要求在已有设计上修订时，才以它为基础。
- **只读输入和本 Skill 的参考文件。**不读取工作区以外的评测目录、参考设计作为样例；格式以本 Skill 的参考文件为准。
- **修订也要完整自查。**在已有设计上修改时，对全文重新执行第 13 步。
- **不在外网处理真实型号代码和文档。**使用云端模型时只处理样例或脱敏材料。
- **部门规定优先。**部门有正式的概要设计模板或设计规范时，以部门规定为准。

## 常见错误做法

| 不应这样写 | 问题 | 应这样写 |
|---|---|---|
| SRS 写“1553B 消息 2 ms 内准备好应答数据”，设计把消息处理放在 50 ms 周期任务中 | 执行方案不满足时间要求，且没有分析 | 第 6.4 节算出最坏情况时延；不满足时改为中断中准备数据或缩短处理间隔 |
| 时序分析写“处理时间很短，满足要求” | 没有路径、没有数值，无法核对 | 写出最坏情况路径和每段时间（估计值注明估计方法），结论“满足（估计，待实测）” |
| “陀螺数据采集：依次读 6 个通道，每个通道等待 2 ms 稳定” | 主循环中忙等 12 ms，其他时间要求无法满足 | 按 tick 分步：每次只切换或读取一个通道，等待由计时判断 |
| “在 10 ms 定时中断中喂狗” | 主循环死循环时中断仍在喂狗，看门狗失效 | 在主循环中喂狗，喂狗间隔小于看门狗最短超时并留余量 |
| 遥控处理和自主控制各自直接写输出寄存器，互锁只在遥控处理中检查 | 自主控制路径绕过了互锁 | 输出寄存器只由一个模块写，互锁在这个模块中检查 |
| SRS 规定姿态角遥测量化单位 0.01°，ICD 规定 0.1°，设计中写“按 0.01° 量化，ICD 由总体修改” | 自行裁决并修改接口 | 列 Q，引用 SRS 和 ICD 原文；暂按其中一份设计并写出另一份的影响 |
| 资源一章写“CPU 负荷约 10%，满足要求” | 没有估算方法 | 列出各任务和中断的执行时间与频率，算出负荷，结论“满足（估计，待实测）” |
| 只把功能类需求写进需求追溯表 | 资源、可靠性、约束类需求没有落实 | 每条需求都要分配到模块；不需要专门模块的，写落实在哪个模块或哪项设计决策中 |
