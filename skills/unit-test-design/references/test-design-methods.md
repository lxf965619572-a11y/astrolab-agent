# 用例设计方法

逐个函数按本文各节设计用例。每节都要有结论：设计了哪些用例，或说明为什么不适用。

## 1 先列被测函数的规定行为

| 项目 | 内容 |
|---|---|
| 输入 | 参数、读取的全局变量、读取的寄存器、下层函数的返回值 |
| 输出 | 返回值、写入的全局变量、写入的寄存器、调用了哪些下层函数和参数 |
| 处理 | 设计规定的规则、检查顺序、计算公式 |
| 状态 | 初值、复位、计数、模式切换 |
| 未规定 | 设计没有说明的情况，列为 Q-xxx |

用例的预期结果全部从这张表推出，不从代码推出。

## 2 等价类

- 每个输入划分有效等价类和无效等价类。
- 一个用例可以覆盖多个有效类；**每个无效类单独一个用例**，其他输入都取有效值，确保失败原因只有一个。
- 枚举型输入（模式、指令码）每个取值都是一类，设计中“其他值”也是一类（如未知指令码、越界的模式值）。

## 3 边界值

| 输入类型 | 要取的值 |
|---|---|
| 区间 [min, max] | min−1、min、max、max+1（类型能表示时） |
| 长度、个数 | 0、1、规定值、规定值 ±1、最大值 |
| 计数器回绕（模 N） | N−1、N（应回到 0），回绕后再加 1 |
| 计数器饱和（上限 N） | N−1、N、N+1（应保持 N） |
| 无符号类型 | 0、最大值（0xFF、0xFFFF、0xFFFFFFFF） |
| 有符号类型 | −1、0、最小值、最大值 |
| 累加、乘法 | 结果正好溢出和不溢出的值 |

边界值要按设计的规定来取：设计写“0～1000 合法”，边界就是 0、1000、1001，不是代码里常量的值。

## 4 判定和条件

### 4.1 语句和分支

- 每个 `if`、`while`、`for`、`?:` 判定，真、假两个方向都要执行到。
- `switch` 的每个 `case` 标签都要单独有用例，包括共用一段代码的多个 `case`（漏掉一个标签的缺陷只有这样才能发现），以及 `default`。
- 循环：执行 0 次、1 次、多次；有上限的循环达到上限。

### 4.2 MC/DC

MC/DC（修正条件/判定覆盖）要求：判定中的每个条件，都有一对用例，只有这个条件的取值不同（其余条件不变或因短路未求值），判定结果也不同。这对用例称为该条件的独立影响对。

- 判定：一个布尔表达式，包括 `if` 条件，以及 `ok = (a > 0) && (b < 10);` 这样的布尔赋值。
- 条件：判定中不含 `&&`、`||` 的布尔子表达式，如 `frame[0] != SYNC_0`。
- C 语言是短路求值，`A && B` 中 A 为假时 B 不求值，记为 X。本 Skill 采用短路求值下的唯一原因 MC/DC：比较一对向量时，在两个向量中都求值了的其他条件必须取值相同，X 不参与比较。
- N 个条件至少需要 N+1 个用例。

**MC/DC 分析表**（编译器不能测量时必须写，用 `check_mcdc` 核对）：

位置：`cmd_check.c` 第 <行号> 行 `if (frame[0] != SYNC_0 || frame[1] != SYNC_1)`（示例，按同步字检查的设计写出）

| 条件 | 含义 |
|---|---|
| A | `frame[0] != SYNC_0` |
| B | `frame[1] != SYNC_1` |

判定：`A || B`

| 用例 | A | B | 判定 | 说明 |
|---|---|---|---|---|
| UT-CMD-CHK-003 | T | X | T | 第 1 字节错，B 不求值 |
| UT-CMD-CHK-004 | F | T | T | 第 2 字节错 |
| UT-CMD-MODE-001 | F | F | F | 正确帧 |

`check_mcdc` 的输入：`decision: "A || B"`，`vectors: [{id:"UT-CMD-CHK-003", values:"TX", expected:true}, {id:"UT-CMD-CHK-004", values:"FT", expected:true}, {id:"UT-CMD-MODE-001", values:"FF", expected:false}]`。

结论：A 由 CHK-003 与 MODE-001 构成独立影响对，B 由 CHK-004 与 MODE-001 构成，满足 MC/DC。

注意：

- `values` 按条件在表达式中出现的顺序写，每个用例的取值要按设计和用例输入推出，不能按想要的结果填。
- 同一个条件在表达式中出现两次（耦合条件）时，按出现位置分别命名，并说明哪些组合不可能出现。
- 条件的取值受其他输入约束而无法独立变化时，在报告中说明，不硬凑向量。

## 5 错误处理和检查优先级

设计规定了多项检查的顺序时（如 空指针 → 长度 → 同步字 → 校验和 → 指令码 → 模式 → 参数）：

- 每项检查单独失败一次，其余检查都通过。
- 相邻两项同时失败，确认返回的是排在前面的错误（如长度错且校验和错，应返回长度错误）。
- 最后一项通过时整体返回成功。

## 6 状态和时序

- **初值**：模块上电后的初始状态要有用例检查，这个用例必须在任何修改状态的用例之前运行，并在用例表中注明。
- **用例相互独立**：其余用例在开头调用复位或初始化函数，显式设置初始状态，不依赖前面用例留下的状态。
- 计数、标志、模式等跨调用保持的状态，测试“连续多次调用”的效果，包括回绕和饱和。
- 有“只在条件满足时才修改状态”的规定时（如“检查函数不修改计数”），要有用例验证状态没有变化。

## 7 字节、位和数据

- 测试数据的高、低字节取不同的值（如 0x1234、0x5A5B），避免 0x0000、0x1111 这类对称值，否则高低字节取反的缺陷发现不了。
- 对“等于某个值”的判断（关键字、魔术字、指定模式），除了正确值，还要取**比它大 1 和比它小 1** 的值各一个，再分别构造只有高字节不同、只有低字节不同的值。只取一侧时，`!=` 被写成 `<` 或 `>` 的缺陷发现不了。
- 位域和掩码：每个有意义的位分别置 1 和清 0。
- 浮点：用 `UT_CHECK_NEAR`，容差取设计规定的精度；设计没有规定精度时列为 Q-xxx。

## 8 自查：用例能否发现常见编码错误

设计完成后，对每个判定和计算问自己：如果代码出现下列错误，哪个用例会失败？没有用例会失败的，补用例。

| 常见错误 | 能发现它的用例 |
|---|---|
| `>` 写成 `>=`，`<` 写成 `<=` | 边界值正好等于常量 |
| `&&` 写成 `||`，漏括号 | MC/DC 的独立影响对 |
| `==` 与 `!=` 写反 | 有效类、无效类各一个 |
| `!=` 写成 `<` 或 `>` | 比规定值大 1、小 1 的值各一个 |
| 漏掉一个 `case` 标签 | 每个标签单独有用例 |
| 字节下标错一位，高低字节写反 | 高低字节取不同值的数据 |
| 计数回绕与饱和写反 | 上限 N 前后各一次 |
| 漏了一项检查 | 只有这一项失败的用例 |
| 检查顺序错 | 两项同时失败的用例 |

评测工具用同样的思路对测试打分（变异得分），因此这一节直接决定测试的质量。
