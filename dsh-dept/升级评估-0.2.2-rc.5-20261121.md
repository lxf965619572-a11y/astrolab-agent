# DSH 升级评估：0.2.1-rc.2 → 0.2.2-rc.5（2026-11-21）

结论：**现在不升级**。0.2.2-rc.5 仍是候选版（npm 的 latest 标签指着它，GitHub 上标为预发布），和我们相关的改动不少，其中两处不改就会出问题（提问工具重复、DSH 自带的 Office 和定时工具进到工作台的会话里）。Win10 真机验收先用现在的 0.2.1-rc.2 做完，升级另作一项工作（见第 4 节）。

依据：GitHub 发布说明（0.2.1-rc.3～0.2.2-rc.5）；`node scripts/dsh-upgrade-check.mjs 0.2.2-rc.5 --skip-runtime`（在 Linux 上装的候选版，所以平台相关的包名有出入，比如 `libreoffice-kit-win32-x64` 显示为“去掉”；真实引擎测试要在 Windows 上跑）。

## 1 升级检查脚本的结果

必须处理 3 项、复核 9 项、通过 32 项。

## 2 对工作台的影响

**必须改的**

1. **提问工具会有两个。** 新版 sdk 模式默认挂上 DSH 自带的 `tool-ask-user`，我们自己又挂了一个（`astrolab-tool-ask-user`，接工作台的提问窗口），模型会看到两个同名的 `ask_user_question`。`engine.mjs` 第 309 行早就写了“DSH 以后若在 sdk 中默认挂上提问工具……升级时检查”。处理：把 DSH 自带的那个加进 TRIMMED_PLUGINS。
2. **DSH 自带的 Office 工具进了 sdk 模式**（`office-kit`、`tool-office`；发布说明 rc.2：“Office 改用原生工具，Web 和 SDK 会话都能用；文档解析在 DSH 主进程里运行，不在命令行沙箱里”）。它和我们的 docreader、docgen 功能重叠，模型会混用；而且在主进程里读文档，**绕过了我们的读取围栏**（read-fence 管的是工具调用，要确认它管不管得到这组工具）。处理：裁掉，Word、Excel、PDF 继续走我们的文档服务。
3. **DSH 自带的定时任务进了 sdk 模式**（`schedule`、`tool-schedule`）。工作台有自己的定时任务，智能体要是用 DSH 的工具建定时，工作台看不到也管不了。处理：裁掉。

**要确认的**

4. **“先读后写”和“外部改动”两道检查默认关了**（alpha.3、rc.1）。智能体可以不读文件就整个覆盖，或者覆盖掉你刚在编辑器里改的内容。我们有任务前快照和审核兜底，但最好按发布说明“需要的 profile 显式恢复”把它们打开。
5. **联网搜索**：rc.2 起默认用 DeepSeek Search API，rc.5 起 DeepSeek 模型用服务端搜索；Web Fetch 也能访问内网地址了。我们把 `tool-web` 关着（检查脚本这项通过）；还要确认走部门模型（pi-ai 的 OpenAI 兼容接口）时请求里不会带上服务端搜索的开关。
6. **会话格式升到 v4**，旧会话打开时迁移，迁移是单向的：升级前先备份任务记录（`%LOCALAPPDATA%\AstroLab` 和开发时的 `runtime\app-data`），退回旧版就打不开迁移过的会话了。
7. **模型请求的 User-Agent 带上启动方式标记**（rc.2），内网模型服务能看出是 SDK 调用。不涉及内容，记一下。
8. **自定义模型不写容量时默认 100 万上下文、12.8 万输出**：我们在 `cordis.patch.yml.template` 里都显式写了（`DEPT_LLM_CONTEXT_WINDOW`、`DEPT_LLM_MAX_TOKENS`），不受影响；局域网 Qwen 那种 13 万的一定要填。
9. **Windows 沙箱**：额外授权的目录只对文件工具生效，不再放宽终端（rc.2）。工作台给技能目录、模板目录的授权如果是靠这个，命令行里就读不到了，真实引擎测试里看。
10. **Node.js 最低 24.9**：安装包里带的是 24.19（`build.log`），够；`scripts/setup.ps1` 的检查还写着“22.19+ 或 24+”，要改成 24.9+；麒麟安装包按打包电脑的 Node 版本下载，打包电脑要先升到 24.9 以上。
11. **部门组合包**：`dsh-dept/package.json` 的 `engines.dsh` 要加新版本；官方 standard 预设改了，`dsh-dept/cordis.patch.yml` 里照抄的部门预设要对照新版重抄（只影响官方桌面端试点那条路线）。

**用不上、不影响的**：AgentTeam、Git worktree 和修改请求、Computer Use、LiveShare、DeepSeek 聊天记录导入、终端面板、移动端界面、六种界面语言、Codex/Claude 委派（实验，sdk 默认没开）。

## 3 安装包大小

LibreOffice 从各平台的原生包（Windows 版 183 MB）换成了 `libreoffice-kit-wasm`，新增 42 个、去掉 9 个包。升级后重新打包时看一下 DSH 部分的大小。

## 4 升级时的步骤（以后做）

1. 在开发电脑（Windows，Node 24.19）上：`node scripts/dsh-upgrade-check.mjs <版本>`（不加 `--skip-runtime`，跑真实引擎测试）。
2. 按第 2 节改：TRIMMED_PLUGINS 加 `tool-ask-user`、`office-kit`、`tool-office`、`schedule`、`tool-schedule`，删 `tool-subagent-list-agents`；恢复先读后写检查；`setup.ps1` 的 Node 版本检查。
3. 再跑一次检查脚本，必须处理为 0；跑 `app` 的测试和 G3 的两个环节（需求分析、研制总结）看成绩有没有变。
4. 改 `config/dsh.json`，运行 `scripts\setup.ps1`，重新打包。

建议等 0.2.2 正式版出来再升（rc 之间还在改破坏性的东西，rc.2 一次就有十几条迁移说明）。
