# oc_ctrl 详细设计评测答案表（不要放进工作区）

输入材料：`sample/design/oc_ctrl/docs/` 下的需求规格说明（SRS）、概要设计说明（HLD）、OC 输出控制器接口说明（ICD）的摘录。逆向模式另有 `sample/design/oc_ctrl/src/`、`include/` 下的代码（由 `prepare.mjs reverse` 放入）。

## 1 正向模式（只给文档，写详细设计）

### 1.1 必须提出的问题（上级文件矛盾或未规定，不能自行决定）

| 编号 | 问题 | 依据 | 正确做法 | 错误做法 |
|---|---|---|---|---|
| F1 | 脉宽范围：SRS 为 20～200 ms，HLD 接口表为 10～200 ms | SRS FUN-022；HLD 4.2 | 列为待确认，引用两处原文；设计中写【待确认】或按 SRS 并注明待确认 | 不提，直接用其中一个 |
| F2 | 正在输出时收到新指令：SRS 要求拒绝，HLD 设计决策要求进入深度 4 的队列 | SRS FUN-023；HLD 4.4-1 | 列为待确认，指出 HLD 与 SRS 矛盾 | 照 HLD 设计队列而不提矛盾 |
| F3 | 回读不一致时的“故障处理”具体做什么（断开该路？计数？上报？重试？）未规定 | SRS FUN-024 | 列为待确认；设计中可写建议做法，但标明待确认 | 自行规定处理方式且不说明 |
| F4 | 指令编号：SRS 为 0～7 对应 OC0～OC7，HLD 接口为 1～8 | SRS FUN-021；HLD 4.2 | 列为待确认，并说明安全模式 OC4～OC7 的判断依赖编号定义 | 照 HLD 写 1～8 不提 |

### 1.2 必须在设计中正确处理的（上级文件已规定）

| 编号 | 内容 | 依据 |
|---|---|---|
| F5 | 写 OUT_SET 后至少等待 2 μs 再回读 OUT_STATE（`delay_us(2)` 或等效） | ICD 3.1 |
| F6 | oc_request/oc_stop_all（主循环）与 oc_tick_isr（中断）共享状态，主循环侧访问要关中断保护，并写明保护范围 | SRS CON-002；HLD 3 |
| F7 | “OC 全部断开”：一次写 OUT_CLR = 0xFF，同时终止当前指令（有队列时清空队列），1 ms 内完成 | SRS FUN-025 |
| F8 | 初始化：先写 OUT_CLR = 0xFF 断开全部通道，再置 CTRL.EN = 1，保证初始化前后输出都断开 | SRS MOD-002；ICD 2 |
| F9 | 脉宽计时的误差分析：输出起点在两个 tick 之间，计数 N 个 tick 后断开，实际脉宽在 (N−1, N] ms，满足 ±1 ms | SRS PER-005 |
| F10 | 三个计数计到 255 后保持 | SRS DAT-007 |
| F11 | 安全模式下拒绝 OC4～OC7（按 SRS 编号） | SRS SAF-005 |

### 1.3 加分项（发现了更好，不扣分）

| 编号 | 内容 |
|---|---|
| B1 | 正在输出 OC4～OC7 时切换到安全模式，是否要立即断开，未规定 |
| B2 | 执行计数在开始输出时加还是输出结束时加，未规定 |
| B3 | 脉宽结束断开后是否也要回读确认，未规定 |
| B4 | 若采用队列（HLD），队列中的指令在中断中启动，回读的 2 μs 延时会落在中断服务程序里，需要评估 |

### 1.4 误报陷阱（材料已写清楚，提出来算误报）

| 编号 | 内容 | 实际规定 |
|---|---|---|
| T1 | 控制器复位状态不明 | ICD 4：EN = 0，全部断开，OUT_STATE 为 0 |
| T2 | OUT_STATE 高位含义不明 | ICD 2：位 8～31 读为 0 |
| T3 | 对外接口函数原型未给出 | HLD 4.2 已给出 |
| T4 | 编程语言未规定 | SRS CON-001：C89 |
| T5 | 共享数据是否需要保护未规定 | SRS CON-002、HLD 3 已规定 |

### 1.5 质量要求

- 5 个对外函数和设计中新增的内部函数，每个都有：原型、功能、输入、输出、处理步骤（编号）、异常处理、调用关系、执行环境（主循环/中断）、需求追溯。
- 全局数据表：每个变量的类型、初值、取值范围、读写者（主循环/中断）、保护方式。
- oc_tick_isr、oc_request 至少有流程图。
- 每个数值都能在 SRS/HLD/ICD 中找到，或在设计决策表中说明理由。
- 写得足够细，单元测试可以直接据此推导预期结果（检查顺序、边界是否含端点、返回值）。

## 2 逆向模式（给代码，补写详细设计）

代码按 HLD 实现，并且有以下问题。详细设计应把它们列为“代码与上级文件不一致”，不能把代码行为当作设计写进去：

| 编号 | 问题 | 代码位置 | 依据 |
|---|---|---|---|
| R1 | 脉宽下限 10 ms（SRS 为 20 ms） | `WIDTH_MIN_MS 10u` | SRS FUN-022（与 HLD 一致，属 F1 矛盾） |
| R2 | 正在输出时新指令进入队列（SRS 要求拒绝） | `oc_request` 队列分支 | SRS FUN-023（与 HLD 一致，属 F2 矛盾） |
| R3 | 写 OUT_SET 后立即回读，没有等待 2 μs | `start_output` | ICD 3.1 |
| R4 | 剩余计数初值为 `width_ms - 1`，实际脉宽在 (N−2, N−1] ms，误差可达 2 ms | `start_output` | SRS PER-005 |
| R5 | `oc_request` 读写共享状态（`s_active`、队列）时没有关中断 | `oc_request` | SRS CON-002 |
| R6 | `oc_stop_all` 没有清空队列，队列中的指令会在下一个 tick 开始输出 | `oc_stop_all` | SRS FUN-025 |
| R7 | 安全模式判断 `id >= 4` 与编号 1～8 的映射（id − 1 为通道号）不一致：禁止的是 id 4～8，即 OC3～OC7，OC3 被错误禁止 | `oc_request` | SRS SAF-005（与 F4 编号矛盾有关） |
| R8 | 三个计数直接自增，到 255 后回绕为 0 | `s_exec_count++` 等 | SRS DAT-007 |
| R9 | 初始化先置 EN = 1 再写 OUT_CLR：软件单独复位而 FPGA 未复位时，原先锁存的输出会在使能瞬间出现 | `oc_init` | SRS MOD-002 |

逆向模式另外检查：设计文档描述的是**应当**的行为（按 SRS/HLD/ICD），代码不一致处单列清单；不能出现“按代码，脉宽下限为 10 ms”这类把代码当依据的写法。
