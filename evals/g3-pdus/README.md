# G3 全流程验收：PDUS 配电单元软件Ⅲ类更改

一个虚构的Ⅲ类软件（XY-9 卫星配电单元软件，以 XY-7 的 V1.00 为基线更改），从需求分析走到研制总结，共 11 个任务，测试 2026-11-03 按部门模板改造后的全部技能：需求分析、详细设计、代码走查、静态分析、追踪表、单元测试、确认测试、研制总结。每个环节都埋了陷阱（缺的资料、矛盾的输入、代码缺陷、错误的数据）。设计理由和答案见 [任务设计.md](任务设计.md)，**跑之前不要给智能体看本目录**。

## 1 准备

- 先确认 `scripts\check.ps1` 通过，AstroLab 中示例工程能打开。
- 在 PowerShell 中查看示例工程位置：`node evals\sample-ws.mjs`。材料会放进其中的 `g3-pdus` 目录，智能体的产出写在 `g3-pdus\out\<环节>`。
- 重新开始：`node evals\g3-pdus\stage.mjs reset --yes`（删除示例工程中的 g3-pdus，含智能体的全部产出）。

## 2 步骤

每一步：先运行 `stage.mjs` 放入材料，它会打印要在工作台上发起的任务描述（复制粘贴即可）；任务做完、审核通过后，运行 `score.mjs` 评分。

| 阶段 | 命令 | 工作台任务 | 评分 |
|---|---|---|---|
| 1 | `node evals\g3-pdus\stage.mjs 1` | 需求分析 | `score.mjs 需求` |
| 2 | `node evals\g3-pdus\stage.mjs 2` | 详细设计 | `score.mjs 设计` |
| 3 | `node evals\g3-pdus\stage.mjs 3` | 代码走查、静态分析、追踪表（编码技能）、单元测试、确认测试设计（五个任务互不依赖） | `score.mjs 走查` / `静态分析` / `追踪表` / `单元测试` |
| 4 | `node evals\g3-pdus\stage.mjs 4` | 确认测试报告（V1.01） | `score.mjs 确认测试` |
| 5 | `node evals\g3-pdus\stage.mjs 5` | 回归测试设计（V1.02） | — |
| 6 | `node evals\g3-pdus\stage.mjs 6` | 回归测试报告（V1.02） | `score.mjs 回归测试` |
| 7 | `node evals\g3-pdus\stage.mjs 7` | 研制总结 | `score.mjs 研制总结` |

说明：

- 阶段 4、6 的执行结果由 `make-exec.mjs` 扮演测试人员生成：读智能体导出的执行记录表和确认测试记录，按答案填写后转成 Excel 放进 `g3-pdus\exec`。它会报告哪些陷阱布置上了；“没能布置”的，说明智能体没有设计对应的用例（如间断超限），记入确认测试设计的评分。
- 研制总结任务中，智能体第一次问完问题、你回答之后，再发一句：“单机测试报告上的日期写错了，实际是 2026-08-12。”（考的是改信息表后重新生成报告。）回答智能体的问题时，只回答数据包里确实有的事实；数据包里没有的（如是否参加系统测试），回答“还没有，先写待补充”。
- 智能体问到需求待确认问题时，按 `materials\2-设计\g3-pdus\released\XY-9配电单元软件需求待确认问题答复单.md` 回答，或回答“等总体答复，先按待确认写”。
- **发起任务前，工作台当前工程必须是“示例工程”**（左上角切换）。任务在当前工程中运行；如果刚用过“我的库”（知识整理、技能创作等），当前工程会停在我的库，智能体会说找不到 g3-pdus。stage.mjs 发现这种情况会提示。
- 每个任务新建一次，技能按 stage.mjs 打印的括号中的模式选。

## 3 评分

`node evals\g3-pdus\score.mjs <环节>`：重跑该技能的检查脚本，按关键词判断陷阱是否处理，判断不了的列为“人工”并给出要看的地方。结果写在 `evals\g3-pdus\results\<时间>-<环节>.md`。关键词判断可能误判，“未通过”的先打开产出核对。

评估记录写在本目录 `评估记录-<日期>.md`，格式参照 `evals\工作台全流程验收-G2-20261029.md`：每个环节的用时、提问、产出、陷阱检出、编造次数、发现的技能问题和处理。

## 4 文件

| 文件 | 说明 |
|---|---|
| `stage.mjs` | 按阶段放材料、打印任务描述 |
| `make-exec.mjs` | 扮演测试人员，生成执行结果 |
| `score.mjs` | 评分 |
| `任务设计.md` | 设计理由、时间线、陷阱和预期（答案） |
| `materials/` | 各阶段的材料（由 `gen/build.py` 生成，已提交，评测时不用重新生成） |
| `code/` | 三个版本的源代码 |
| `gen/` | 文档模板（`*.tpl.md`，`N|`/`O|` 行和 `{{N:…||O:…}}` 区分 XY-9 和 XY-7 两个版本）、数据包源文件、生成脚本 |
| `results/` | 评分结果和执行记录（不提交） |
