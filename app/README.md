# AstroLab 工作台（阶段 2）

Electron + React 的桌面工作台。引擎是 DSH 的 sdk 模式（阶段 0、S6 验证通过），技能、工具服务、模型路由沿用本仓库的 `skills/`、`mcp/`、`config/`。

```powershell
powershell -ExecutionPolicy Bypass -File app\dev.ps1          # 实机：调用部门模型
powershell -ExecutionPolicy Bypass -File app\dev.ps1 -Mock    # 模拟引擎：不调用模型，看界面和流程
```

第一次运行会 `npm install`（下载 Electron 约 100 MB）。之后每次只重新编译界面（约 2 秒）再启动。

## 目录

## 数据放在哪

- 用户数据：安装版在 `%LOCALAPPDATA%\AstroLab`（Linux：`~/.local/share/AstroLab`）；用 `dev.ps1` 开发时在仓库的 `runtime\app-data`（不提交）。内容：项目清单、任务记录、DSH 会话、示例工程副本、日志
- 示例工程：首次运行把仓库的 `sample` 复制到数据目录下的 `workspace\sample`，建成 Git 仓库
- 排查问题：数据目录下的 `logs\main.log`（主进程）、`logs\<任务>.jsonl`（引擎收发），以及 `runtime\app-dev.log`（dev.ps1 输出）

## 界面：一个输入框，按需选技能

和 Claude 一样：左栏是“新任务”（Ctrl N）和最近的任务（按今天、昨天、最近 7 天分组，显示所用技能和状态），底部是知识库、技能与插件、全部任务。发起页一个输入框：

- **选技能**：点“常用技能”卡片；或在输入框里打 `/` 选；或点“技能”按钮按类别搜。一次最多 3 个（比如“编码 + 单元测试”）。
- **本地推荐**：没选技能时，工作台按描述在本地推荐（和知识库一样的分词，比对技能的名称、关键词和描述；不调用模型，结果确定），按 Tab 选第一个。
- **追问也能选**：任务做完或进行中，对话下面的输入框同样可以打 `/` 选技能、点“技能”“添加文件”。发给智能体时附上“先用 skill 工具加载技能 X”和相关文件清单（插话经引擎桥送到，DSH 不展开 `/技能名`），对话里只显示你写的那句和一行“（技能：…；文件：…）”；用到的技能记到任务上
- **不选也行**：智能体会先看有哪些部门技能，合适就加载，并在开头说明用了哪个；做到一半需要别的技能也会自己加载。
- **研制环节**不再是导航，而是技能的类别（需求、设计、编码、测试、走查、文档与图、创作、其他），用于常用技能的排序、任务历史的筛选和图标。老任务按原来的环节归类。
- **常用**：内置的 6 个研制技能默认是常用；在“技能与插件 → 已安装”里可以把任何技能（或插件带的技能）设为常用或取消。

技能怎么显示，由 SKILL.md 头信息决定：`title`（显示名）、`category`（类别）、`summary`（卡片上的一句话）、`keywords`（推荐用）、`placeholder`、`hint`、`report`（出报告时开关上的文字）、`pinned`（默认放进常用）。都是可选的，没写时用 name 和 description 推出来。值里不要有英文冒号加空格和 `#`（引擎按 YAML 读）。

## 知识库、技能与插件

三样东西放在同一种“库”里：一个库是一个 Git 仓库，`knowledge/`（经验、设计、代码、问题，每条一个 Markdown 文件）、`skills/`（技能）、`plugins/`（插件 = 技能 + 工具服务 + 模板）。

- **我的库**：`<数据目录>\library\mine`，本机的 Git 仓库，只有自己能看到。智能体在任务中记的经验草稿、自己做的技能和插件都先放这里
- **共享库**：内网 Git 服务器上的仓库（部门通用库、各型号库）。部门预置的列表放在 `config\libraries.json`（格式见 `config\libraries.example.json`），用户也可以在“技能与插件 → 共享库”里自己加。打开工作台时在后台同步，连不上也不影响使用
- **权限**：型号库只给相关的人开权限，克隆不了就看不到；型号相关的条目只能提交到对应的型号库
- **审核**：提交 = 把条目从我的库复制到共享库的一个新分支 `submit/<用户>/<名字>-<时间>`；审核人在“技能与插件 → 审核”里看改动（插件的工具服务代码要逐行看），通过 = 合并进主分支，退回 = 删掉分支。主分支建议在 Git 服务器上设为保护分支，只有审核人能推送；审核人也可以在服务器的合并请求页面处理
- **智能体怎么用**：知识库工具服务 `mcp/knowledge`（不依赖 npm 包）提供 `search_knowledge`、`read_knowledge`、`propose_knowledge`；发给智能体的第一条消息提醒它动手前先查；**不主动记**，只有用户在对话里说“记到知识库”“入库”时才记成草稿（任务的中间产物多半不值得入库）。草稿在“知识库”里确认后才算数
- **安装**：技能和插件复制到 `<数据目录>\installed`，引擎重新加载后生效（任务进行中会等它结束）。插件的工具服务只能用 node 运行插件目录里的脚本
- **创作**：“做一个技能 / 做一个插件”会把我的库当作项目打开，用内置的 `skill-authoring`、`plugin-authoring` 技能和你一起写，写完照常审核、提交到我的库；试用满意再提交到共享库
- **共享库的初始化**：在 Git 服务器上建一个空仓库（主分支 `main`），推一个只有 `README.md` 的初始提交即可，目录由工作台按需创建
- **知识整理（蒸馏）**：“知识库 → 待整理 → 整理最近的任务”。工作台从上次整理之后结束的任务里挑信号写成素材（`我的库\.distill\`，不进 Git）：人在审核时改了智能体的产物（任务结束时的版本记在 `refs/astrolab/ends/<任务>`，和提交的版本比）、改动被整个恢复、中途的插话和对提问的回答、出错的操作。再在我的库里发起“知识整理”任务（技能 `knowledge-distill`），候选写到 `我的库\待整理\<日期>\`，报告写 `待整理\<日期>-整理报告.md`，工作台提交。候选不在 `knowledge/` 下，智能体检索不到；采纳（缺来源的不能采纳）才移进 `knowledge/<类别>/`。用公网接口时只整理示例工程的任务（`ASTROLAB_DISTILL_SCOPE=sample|all` 可以改）
- **资料库**（和知识库分开）：知识库放部门提炼的结论（照着做），资料库放学习资料、标准的原文（出处，引用写资料名、节号和页码）。资料库是一个共享库，原文按节切开放在 `reference/<资料>/`，每节带资料名、节号、印刷页码、许可（公版 / 仅部门内部）。“知识库 → 资料”页按资料和章节浏览、检索、阅读、复制引用；智能体用 `search_reference`、`read_reference`、`list_references` 查（第一条消息提醒它需要依据时查）。原文多是英文：检索时中文问题里的术语按 `config/glossary-zh-en.json`（和资料库里的 `reference/glossary.json`）补上英文。用公网接口时有版权的资料智能体检索不到（`ASTROLAB_REFERENCE_SCOPE=public|all` 可以改）。导入见 `scripts/reference/`：每份资料一个导入说明 `config/reference-specs/<id>.json`（书目信息和目录，原文不进仓库），`node scripts/reference/build.mjs <资料库目录>` 导入并提交；检索评测 `node evals/reference/run.mjs`（11-02 首批 18 题，前 3 命中 94%）
- **资料阅读器**（“资料”页右边）：原文 / 中文 / 对照三种看法。“翻译成中文”直接调部门模型（`app/main/llm.mjs`），按段分组、带上术语表，逐段对齐（对照视图一行一段）；有版权的资料用公网接口时不翻译。选中文字出工具条：四种颜色高亮、写批注；点高亮改颜色、改批注、删除；每节底下是本节摘录。可以改原文（修正提取出错的公式、断词）和改译文。个人的东西叠在资料库上（资料库同步会冲掉本地改动）：改过的原文和译文在 `我的库\reference\<资料>\<节>.md`、`<节>.zh.md`，高亮和批注在 `<数据目录>\reference-notes\`，同时写一份 `我的库\摘录\<资料>.md`（Obsidian 里能看）。改过的原文、译文可以“提交到资料库”走审核；资料库里审核过的 `<节>.zh.md` 是部门译文，大家直接用，也进检索（中文问题直接命中）
- **Obsidian**：我的库可以直接当 Obsidian 的库打开（“知识库”页的 Obsidian 按钮，第一次会提示怎么加）。条目头信息兼容 Obsidian 的属性面板（多行列表的标签也认）；在 Obsidian 里改的条目工作台每 3 分钟提交一次；把候选拖进 `knowledge/` 下的类别文件夹就算采纳（提交时去掉“候选”）；`.obsidian/`、`.trash/` 不进 Git。共享库在 Obsidian 里只能看：同步会丢掉本地改动（`.obsidian` 设置保留）

## 读取范围和精简（harness）

**读取围栏**。DSH 的沙箱只管写（文件工具“reads pass through”，Windows ACL 沙箱也只限制写），智能体原本读得到电脑上的任何文件：别的工程、`config\local.env`、`evals\`。编码评测里真的发生过：工作区缺输入时，智能体去仓库根目录找了。`read-fence.mjs` 挂在 DSH 工具流水线的 guard 上（单调：拒绝了谁也改不回），每次工具调用（含嵌套调用）先检查：

- 文件工具（read、grep、glob、read_image、working_directory、subagent 的 cwd、写和改）和 MCP 工具名字像路径的参数、cflags 里的 `-I`：展开联接和符号链接后，必须在工作区、技能目录或临时目录里
- 命令行（pwsh、bash）：命令里的绝对路径、跳出工作区的 `..`、`~`、`$env:USERPROFILE` 一类变量、网络路径，必须在上面的目录或工具链目录（node、gcc、Cppcheck、系统目录、Program Files）里
- 拒绝时告诉智能体用 ask_user_question 请用户把文件放进工作区；任务的第一条消息里也写了这条约定

局限：命令行检查看的是命令文本，挡得住正常的“去别处找找”，挡不住刻意在运行时拼出来的路径；工具服务进程自己读文件不经过它（我们的服务各自限制目录）。内核级的读隔离要 AppContainer，DSH 目前没有。验证：`node app/test/real-dsh-fence.mjs`（真实 DSH，7 项）。

**精简**。关掉部门用不上的 DSH 插件（`engine.mjs` 的 `TRIMMED_PLUGINS`，每项写了理由）：workflow、目标（goal）、计划模式、MCP 资源、list_agents、subagent_fork。`send_message`、`interrupt_agent` 保留——subagent 的说明要子智能体用它报告结果。量法：`node app/test/measure-request.mjs <标签>`（真实 DSH + 假模型，不花模型调用）。

|---|---|---|
| 工具 | 35 个 | 25 个 |
| 工具定义 | 27,294 字 | 18,450 字（−32%） |
| 系统提示 | 2,578 字 | 1,499 字（计划模式、目标的说明随插件去掉） |

## Git 防护

智能体不能自己提交、建分支或改引用；人照常用自己的 Git 工具或审核页提交。

- 钩子 `git-hooks/reference-transaction`：在任何引用更新（提交、建分支、reset、stash 等）之前运行，`--no-verify` 跳不过。判断依据是 DSH 给智能体的每条命令行都设的 `DSH_SHELL=1`、`DSH_SESSION_ID`；工作台自己的 Git 操作带 `DEPT_UI_GIT=1` 放行。和 `dsh-dept` 共用同一份钩子（LF 换行，见 `.gitattributes`）。
- 加入项目时安装（`main/git.mjs` 的 `installGuardHook`）；旧版本的钩子按内容摘要认出来自动升级。仓库已有别的同名钩子、或设了共用钩子目录 `core.hooksPath` 时不动，界面提示原因。
- 防误操作，不防恶意：在命令里清掉这些变量就能绕过。钩子也挡不住 `reset --hard` 这类丢弃未提交改动的命令，所以每个任务前记快照。
- 测试：`npm test` 里的 `git.test.mjs`（智能体提交和建分支被拦、人和界面的提交正常、旧钩子升级、别人的钩子不动）。

## 不往外发数据

- sdk 模式没有 DSH 的产品埋点插件。
- 会话遥测（点赞、点踩时上传会话）：`paths.mjs` 设 `DSH_TELEMETRY_MODE=DISABLED`，引擎补丁里 `session-telemetry-otel` 也设 `mode: DISABLED`。
- 官方 API 请求附带的会话日志（`session-log-deepseek`）：补丁里 `enabled: false`。只在走官方 DeepSeek 路由时才会发，工作台用 dept-llm，这是双保险。查过 AstroLab 的 10 个会话，没有发生过。

## 插话、停止和引擎启动

- 插话：经引擎桥 steer，在智能体的下一步之前送到（sdk 的 session/prompt 要等整轮做完才看到）
- 停止：经引擎桥 cancel，只中止当前这一轮，引擎进程不退出，继续不用重启；桥不可用或 3 秒内停不下来才结束进程
- 引擎：打开项目时在后台启动（冷启动要等工具服务和技能加载完，实测第一次超过 1 分钟），任务之间共用；状态栏显示引擎状态
- 主进程日志 `logs\main.log` 记录引擎每次启动用时和引擎桥连接

## 麒麟（Linux）和局域网模型

同一份程序在 Linux 上运行（11-16 在 Linux x64 上实测：Electron 窗口、窗口控件覆盖层、真实 DSH 引擎、工具服务）。和 Windows 的差别：

- 安装布局 `tools/node/bin/node`；gcc、cppcheck、git、bubblewrap 用系统的（安装包可带离线包）。打包、安装、自检见 `packaging/麒麟部署说明.md`
- DSH 在 Linux 上用 bash 执行命令，命令沙箱是 bubblewrap 或 Landlock（Windows 是 ACL）；两者都不可用时 DSH 拒绝执行命令
- 标题栏：Windows 和 Linux 都用窗口控件覆盖层；`ASTROLAB_NATIVE_FRAME=1` 改用系统标题栏，`ASTROLAB_DISABLE_GPU=1` 关 GPU 加速
- 局域网 Qwen3.8-27B：`DEPT_LLM_THINKING_FORMAT=qwen-chat-template`（发 `enable_thinking`、`preserve_thinking`），上下文和输出上限按服务端改；**设置 → 模型 → 检测模型** 逐项检查。验证：`node app/test/real-dsh-qwen.mjs`（真实 DSH + 假 vLLM，看发出去的参数和思考的往返）、`node --test app/test/probe.test.mjs`
- 浏览器里看界面时，地址加 `?scenario=kylin-qwen` 模拟这个场景（演示、截图用）

## 模型配置（设置 → 模型）

- **部门默认**：设置文件 local.env 的 `DEPT_LLM_*`，管理员改；列表第一项，不能删。
- **自定义模型**：“添加模型”从预设开始（局域网 Qwen3.8-27B、内网 DeepSeek、DeepSeek 官方接口、其他 OpenAI 兼容接口），填地址后“获取模型列表”（读服务端 /models，自动带出上下文和思考参数写法），“检测”逐项查模型、上下文、工具调用、思考，有建议可以一键采用；“保存并使用”后引擎用新模型重启（任务进行中的等这一轮结束）。
- **存放**：用户数据目录的 `models.json`；密钥用 Electron safeStorage 加密（Windows DPAPI、Linux 密钥环），系统不支持时明文并只给本人读写，和 local.env 一样。密钥不回到界面。
- **锁定**：部门要统一模型时在 local.env 写 `ASTROLAB_MODEL_LOCK=1`，设置页只读、只用部门默认。
- 验证：`node --test test/models.test.mjs`；11-16 在 Linux 上用安装好的工作台（真实 DSH + 两个假 vLLM）走过：界面里加“内网 DeepSeek”、检测、保存并使用 → 引擎重启 → 新任务的请求都发到了新服务、用新模型名。

## 源码保护（麒麟部署，`--protect`）

不想把工作台源码随安装包发出去时，打包加 `--protect`（`packaging/linux/protect.mjs`）：主进程、预加载、引擎、各工具服务编成 **V8 字节码**（用安装包自带的 Electron、node 编，和运行时同一套 V8）；引擎桥、读取围栏、更新器、自检改为**压缩代码**（DSH 按 ESM 文件加载桥和围栏，换字节码可能让读取围栏悄悄失效，不冒险）；界面本就是 Vite 压缩产物；技能和配置不动（技能是 Markdown，运行时要读原文）。装好的包里 grep 不到可读的工作台源码。界限：本地程序没法绝对不可破，有 root 的人总能取到运行时文件，字节码挡的是常规查看和复制。细节见 `packaging/麒麟部署说明.md`。11-16 在 Linux 上验证：字节码包能启动、真实引擎跑通单元测试任务、调用字节码工具服务。

## 定时任务（自动化）

侧栏“定时任务”。做法参照 Claude 的定时任务：到点在指定工程里自动发起一个任务，做完照常进审核，人回来再看、再提交。

- **新建**：名称、每次运行要做什么（写成单独能看懂的一段：每次运行都是新任务，不记得上次的对话）、技能（可不选）、工程、模式、运行频率（每小时 / 每天 / 工作日 / 每周几 / 只跑一次 / 仅手动）。“模板”里有部门常用的四种：每晚静态分析巡检、改动代码走查、每周研制进展、设计与代码一致性，结果都写在工程的 `巡检/` 下，不改源代码和设计。
- **立即运行**：每一行的 ▶，试运行或临时补做；工程被占用时直接报错，不排队。
- **运行记录**：点一行展开，最近 30 次（开始、补跑、手动、跳过、没能运行），带任务现在的状态（进行中、待审核、已提交、已恢复）；点一条打开那次的任务。任务页标题下有“定时”标记。
- **无人值守**（`task.mjs` 的 `unattendedNote`）：第一条消息里换掉“需要我拍板时提问”，改为不提问、按最合理的理解做、把假设写进最后回复的“待确认”；删除或覆盖用户内容这类不可撤销又两可的决定不做，写清楚要人决定什么；没有要做的事就说明后结束。智能体还是提了问：没人在看就马上自动回答“按最合理的做法继续”；有人正看着这个任务（窗口在前台、5 分钟内动过键盘鼠标）先等 2 分钟让人答。用户在这个任务里追问，就算人回来了，之后的提问照常等人回答。Git 防护、读取围栏、任务前快照都照旧，智能体提交不了。
- **什么时候跑**：软件开着、电脑醒着时，每 30 秒检查一次，电脑从睡眠醒来、解锁时马上查一次。到点晚了 10 分钟以内照常跑；更晚的算错过，不管错过几次只补跑最近一次（7 天内，记录和通知里写“补跑”），超过 7 天只记“错过”。“只跑一次”的跑完自己停用。
- **忙的时候**：工程里有任务在进行（你在用，或别的任务）、同时进行的任务已满（`ASTROLAB_MAX_PARALLEL`）、或你正对着这个工程（窗口在前台、5 分钟内有操作，免得把你在看的任务换掉）：排队，每 30 秒再试，最多等 2 小时，超时记“跳过”。同一个定时任务上一次的运行还没做完：这次跳过。
- **后台运行**：有启用的定时任务时出现托盘图标，关窗口只是缩到托盘（第一次会提示），定时任务和进行中的任务照常做；托盘菜单有“打开”“定时任务”“下一个：…”“退出”。定时任务运行期间用 `powerSaveBlocker` 阻止系统睡眠（屏幕可以关）。定时任务页底部“开机自动启动”：Windows 用登录项，Linux 写 `~/.config/autostart/astrolab.desktop`，都带 `--hidden`（只在托盘里启动，不弹窗口）；开发时（`dev.ps1`）不能设置。
- **通知**：做完时系统通知“定时任务“…”做完了，等你审核”，点一下打开那个任务；没能运行（工程不在了、技能卸载了）也通知。
- 测试：`node --test test/schedule.test.mjs`（下次运行时间、补跑、排队、跳过、只跑一次、仅手动）；`task.test.mjs` 末尾两项（无人值守的第一条消息、自动回答、有人看着时等人答、追问后解除）。界面在浏览器里看：`?nosched` 从空的开始。
- 还没做：按 Git 新提交触发；唤醒睡眠中的电脑（要用系统任务计划，Windows 和麒麟各做一套）；每个定时任务选模型。
