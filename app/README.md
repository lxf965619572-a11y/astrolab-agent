# AstroLab 工作台（阶段 2）

Electron + React 的桌面工作台。引擎是 DSH 的 sdk 模式（阶段 0、S6 验证通过），技能、工具服务、模型路由沿用本仓库的 `skills/`、`mcp/`、`config/`。

```powershell
powershell -ExecutionPolicy Bypass -File app\dev.ps1          # 实机：调用部门模型
powershell -ExecutionPolicy Bypass -File app\dev.ps1 -Mock    # 模拟引擎：不调用模型，看界面和流程
```

第一次运行会 `npm install`（下载 Electron 约 100 MB）。之后每次只重新编译界面（约 2 秒）再启动。

## 目录

| 目录或文件 | 作用 |
|---|---|
| `engine/engine.mjs` | 引擎进程（JSON-RPC over stdio）、引擎桥的管道服务端、引擎启动补丁（提问工具、引擎桥、读取围栏，关掉联网工具和用不上的插件 `TRIMMED_PLUGINS`） |
| `engine/read-fence.mjs` | 运行在 DSH 进程里的读取围栏插件：智能体只读得到工作区、技能目录、临时目录和工具链目录 |
| `engine/bridge.mjs` | 运行在 DSH 进程里的引擎桥插件：提问转给工作台；插话在下一步之前送到（steer）；停止只中止当前轮（cancel） |
| `engine/activity.mjs` | 把会话事件整理成活动记录（同类合并、思考用时、越界标出、写文件统计、计划进度） |
| `engine/mock-dsh.mjs` | 模拟引擎：按 sdk 协议回放剧本，测试和看界面用 |
| `main/main.mjs`、`preload.cjs` | Electron 主进程、界面能调用的全部接口 |
| `main/task.mjs` | 任务控制器：状态、停止与继续、插话、提问、快照、审核、提交、历史；打开项目就预热引擎，任务之间共用 |
| `main/git.mjs` | 任务前快照（不建分支、不动暂存区）、相对快照的改动和差异、恢复、只提交任务改动、防护钩子 |
| `main/projects.mjs` | 项目清单、加入项目时的文件夹权限和钩子、示例工程、任务描述里提到的文件 |
| `main/library.mjs` | 库：我的库、共享库（内网 Git）的同步，提交审核、通过、退回，技能和插件的目录、安装、卸载 |
| `main/paths.mjs` | 开发与安装两种布局、用户数据目录、设置文件、DSH 数据目录补丁 |
| `src/` | 界面（React + TypeScript）：发起、进行中、审核、历史、知识库、技能与插件；提问卡片、提示条、声音、三套皮肤（浅紫、奶油、陶土） |
| `test/` | `npm test`：引擎层、引擎桥、Git、任务控制器、库（本机裸仓库当 Git 服务器）、知识检索、编码自查脚本、读取围栏；`node app/test/real-dsh.mjs`：在真实 DSH 上验证插话、停止、继续、提问、知识库工具、安装的技能和插件（假的模型服务，不花模型调用）；`real-dsh-fence.mjs`：读取围栏；`measure-request.mjs`：量第一个请求 |

## 数据放在哪

- 用户数据：安装版在 `%LOCALAPPDATA%\AstroLab`；用 `dev.ps1` 开发时在仓库的 `runtime\app-data`（不提交）。内容：项目清单、任务记录、DSH 会话、示例工程副本、日志
- 示例工程：首次运行把仓库的 `sample` 复制到数据目录下的 `workspace\sample`，建成 Git 仓库
- 排查问题：数据目录下的 `logs\main.log`（主进程）、`logs\<任务>.jsonl`（引擎收发），以及 `runtime\app-dev.log`（dev.ps1 输出）

## 界面：一个输入框，按需选技能

和 Claude 一样：左栏是“新任务”（Ctrl N）和最近的任务（按今天、昨天、最近 7 天分组，显示所用技能和状态），底部是知识库、技能与插件、全部任务。发起页一个输入框：

- **选技能**：点“常用技能”卡片；或在输入框里打 `/` 选；或点“技能”按钮按类别搜。一次最多 3 个（比如“编码 + 单元测试”）。
- **本地推荐**：没选技能时，工作台按描述在本地推荐（和知识库一样的分词，比对技能的名称、关键词和描述；不调用模型，结果确定），按 Tab 选第一个。
- **不选也行**：智能体会先看有哪些部门技能，合适就加载，并在开头说明用了哪个；做到一半需要别的技能也会自己加载。
- **研制环节**不再是导航，而是技能的类别（需求、设计、编码、测试、走查、文档与图、创作、其他），用于常用技能的排序、任务历史的筛选和图标。老任务按原来的环节归类。
- **常用**：内置的 6 个研制技能默认是常用；在“技能与插件 → 已安装”里可以把任何技能（或插件带的技能）设为常用或取消。

技能怎么显示，由 SKILL.md 头信息决定：`title`（显示名）、`category`（类别）、`summary`（卡片上的一句话）、`keywords`（推荐用）、`placeholder`、`hint`、`report`（出报告时开关上的文字）、`pinned`（默认放进常用）。都是可选的，没写时用 name 和 description 推出来。值里不要有英文冒号加空格和 `#`（引擎按 YAML 读）。

## 知识库、技能与插件

三样东西放在同一种“库”里：一个库是一个 Git 仓库，`knowledge/`（经验、设计、代码、问题，每条一个 Markdown 文件）、`skills/`（技能）、`plugins/`（插件 = 技能 + 工具服务 + 模板）。

- **我的库**：`<数据目录>\library\mine`，本机的 Git 仓库，只有自己能看到。智能体在任务中记的经验草稿、自己做的技能和插件都先放这里
- **共享库**：内网 Git 服务器上的仓库（部门通用库、各型号库）。部门预置的列表放在 `config\libraries.json`（格式见 `config\libraries.example.json`），用户也可以在“技能与插件 → 共享库”里自己加。打开工作台时在后台同步，连不上也不影响使用
- **权限**：型号库只给相关的人开权限，克隆不了就看不到；型号相关的条目只能提交到对应的型号库
- **审核**：提交 = 把条目从我的库复制到共享库的一个新分支 `submit/<用户>/<名字>-<时间>`；审核人在“技能与插件 → 审核”里看改动（插件的工具服务代码要逐行看），通过 = 合并进主分支，退回 = 删掉分支。主分支建议在 Git 服务器上设为保护分支，只有审核人能推送；审核人也可以在服务器的合并请求页面处理
- **智能体怎么用**：知识库工具服务 `mcp/knowledge`（不依赖 npm 包）提供 `search_knowledge`、`read_knowledge`、`propose_knowledge`；发给智能体的第一条消息提醒它动手前先查；**不主动记**，只有用户在对话里说“记到知识库”“入库”时才记成草稿（任务的中间产物多半不值得入库）。草稿在“知识库”里确认后才算数
- **安装**：技能和插件复制到 `<数据目录>\installed`，引擎重新加载后生效（任务进行中会等它结束）。插件的工具服务只能用 node 运行插件目录里的脚本
- **创作**：“做一个技能 / 做一个插件”会把我的库当作项目打开，用内置的 `skill-authoring`、`plugin-authoring` 技能和你一起写，写完照常审核、提交到我的库；试用满意再提交到共享库
- **共享库的初始化**：在 Git 服务器上建一个空仓库（主分支 `main`），推一个只有 `README.md` 的初始提交即可，目录由工作台按需创建

## 读取范围和精简（harness）

**读取围栏**。DSH 的沙箱只管写（文件工具“reads pass through”，Windows ACL 沙箱也只限制写），智能体原本读得到电脑上的任何文件：别的工程、`config\local.env`、`evals\`。编码评测里真的发生过：工作区缺输入时，智能体去仓库根目录找了。`read-fence.mjs` 挂在 DSH 工具流水线的 guard 上（单调：拒绝了谁也改不回），每次工具调用（含嵌套调用）先检查：

- 文件工具（read、grep、glob、read_image、working_directory、subagent 的 cwd、写和改）和 MCP 工具名字像路径的参数、cflags 里的 `-I`：展开联接和符号链接后，必须在工作区、技能目录或临时目录里
- 命令行（pwsh、bash）：命令里的绝对路径、跳出工作区的 `..`、`~`、`$env:USERPROFILE` 一类变量、网络路径，必须在上面的目录或工具链目录（node、gcc、Cppcheck、系统目录、Program Files）里
- 拒绝时告诉智能体用 ask_user_question 请用户把文件放进工作区；任务的第一条消息里也写了这条约定

局限：命令行检查看的是命令文本，挡得住正常的“去别处找找”，挡不住刻意在运行时拼出来的路径；工具服务进程自己读文件不经过它（我们的服务各自限制目录）。内核级的读隔离要 AppContainer，DSH 目前没有。验证：`node app/test/real-dsh-fence.mjs`（真实 DSH，7 项）。

**精简**。关掉部门用不上的 DSH 插件（`engine.mjs` 的 `TRIMMED_PLUGINS`，每项写了理由）：workflow、目标（goal）、计划模式、MCP 资源、list_agents、subagent_fork。`send_message`、`interrupt_agent` 保留——subagent 的说明要子智能体用它报告结果。量法：`node app/test/measure-request.mjs <标签>`（真实 DSH + 假模型，不花模型调用）。

| | 精简前 | 精简后 |
|---|---|---|
| 工具 | 35 个 | 25 个 |
| 工具定义 | 27,294 字 | 18,450 字（−32%） |
| 系统提示 | 2,578 字 | 1,499 字（计划模式、目标的说明随插件去掉） |
| 第一个请求 | 37,747 字节 | 27,774 字节（−26%） |

（Linux 上量的，缺 cppcheck、docreader、docgen 三个工具服务；前后同一配置，差值可比。每一步都重发这些定义，越短越省上下文和预填充时间。）

## Git 防护

智能体不能自己提交、建分支或改引用；人照常用自己的 Git 工具或审核页提交。

- 钩子 `git-hooks/reference-transaction`：在任何引用更新（提交、建分支、reset、stash 等）之前运行，`--no-verify` 跳不过。判断依据是 DSH 给智能体的每条命令行都设的 `DSH_SHELL=1`、`DSH_SESSION_ID`；工作台自己的 Git 操作带 `DEPT_UI_GIT=1` 放行。和 `dsh-dept` 共用同一份钩子（LF 换行，见 `.gitattributes`）。
- 加入项目时安装（`main/git.mjs` 的 `installGuardHook`）；旧版本的钩子按内容摘要认出来自动升级。仓库已有别的同名钩子、或设了共用钩子目录 `core.hooksPath` 时不动，界面提示原因。
- 防误操作，不防恶意：在命令里清掉这些变量就能绕过。钩子也挡不住 `reset --hard` 这类丢弃未提交改动的命令，所以每个任务前记快照。
- 测试：`npm test` 里的 `git.test.mjs`（智能体提交和建分支被拦、人和界面的提交正常、旧钩子升级、别人的钩子不动）。

## 不往外发数据

- sdk 模式没有 DSH 的产品埋点插件。
- 会话遥测（点赞、点踩时上传会话）：`paths.mjs` 设 `DSH_TELEMETRY_MODE=DISABLED`，引擎补丁里 `session-telemetry-otel` 也设 `mode: DISABLED`。
- 官方 API 请求附带的会话日志（`session-log-deepseek`）：补丁里 `enabled: false`。只在走官方 DeepSeek 路由时才会发，工作台用 dept-llm，这是双保险。查过 AstroLab 的 10 个会话，没有发生过。

## 插话、停止和引擎启动

- 插话：经引擎桥 steer，在智能体的下一步之前送到（sdk 的 session/prompt 要等整轮做完才看到）
- 停止：经引擎桥 cancel，只中止当前这一轮，引擎进程不退出，继续不用重启；桥不可用或 3 秒内停不下来才结束进程
- 引擎：打开项目时在后台启动（冷启动要等工具服务和技能加载完，实测第一次超过 1 分钟），任务之间共用；状态栏显示引擎状态
- 主进程日志 `logs\main.log` 记录引擎每次启动用时和引擎桥连接

## 已知限制

- 命令面板（Ctrl K）、`@` 引用文件的弹出提示还没做
- 一次只运行一个任务（运行中可以切到别处，先写好下一个任务）；越界操作提示里说的“把该目录加入项目”还没有按钮
- 审核里的疑似缺陷清单需要技能输出结构化结果，现在显示智能体最后一条回复
- 评测页、Word 模板配置、更新、诊断包（需求规格说明 G3、G4 的部分）还没做；整体进度见仓库根目录的 `项目上下文.md`
